# Codex 模块定义与划分审查报告

审查基准：`docs/` 下 4 份 PDF。`SPEC_TRANSFER_PROTOCOL_V1.5.pdf` 为协议权威，`HUB_NOC.pdf`、`HUB_RHUB.pdf` 为模块合同，`DATA_LAYOUT_V1.5.pdf` 为存储格式参考。
审查对象：`docs/hub_spec/*.md`（00–07、README）以及 `docs/00–04_*易读版.md`。
页码取 PDF 页脚 "n / 总页数"，与 pdftotext 分页一致。
严重度：高 = 会直接导致 RTL 边界、吞吐或归属出错；中 = 合同缺项或数值、语义偏差；低 = 表述、标签、命名问题。

## 1. 总体结论

顶层划分方向正确：中央 L2 为中心的两级互连，hub 一篇（DN/UP/ATT/SYNC），R-hub 单独一篇。侧带位宽 12/14 bit、信用粒度、10/4 根返还线、WCNT/RCNT 在 L2 侧、watchdog 归 LIC、训练权重不经 hub，这些关键归属都写对了。

问题集中在下面四类：

1. 自行引入了一层叶子模块拆分，并标成"已定"。PDF §0 明确写了"hub 内部不再细拆"。
2. HUB-DN 和 R-hub 的状态机被写成串行单链，与 PDF 要求的流水吞吐和在途表机制冲突。
3. 职责与合同遗漏较多。HUB-DN 的读回、表装载、门限口没有写；份释放直达 NI SDN 的通路没有写；§6 的 11 份对外合同只覆盖了 4 份；L1 集成篇的归属没有写。
4. 若干数值或语义被改写。包括共享池限速、上行信用粒度、GO 方向、R-hub 信用返还归属、缺位 +0；部分不确定性标签也被丢掉。

共 48 条发现：高 9 条，中 23 条，低-中 2 条，低 14 条。

## 8. 核对一致的内容

- 拓扑：两级集中、核间无直连、hub 中心无集中判决或采样单元（HUB_NOC p1 §1.1）。
- 侧带：下行 12 bit（mask 4 / VC 2 / class 3 / last 1 / nw8 2），上行 14 bit（多出属主 2 bit、区域 4 bit），不带地址（p8 §4.1.6）。
- 地址：下行地址由核侧落地口生成；上行由 HUB-UP（核,区域）游标生成，环写时区域号即环号。
- 信用：VC0/1 按（核,VC,道），VC2/3 按（核,VC）共享池，下行每核 10 根、上行每核 4 根返还线，单拍脉冲（hub_spec/01:84-86）。
- 多播逐目的扣信用，末 flit 全部返还后报 RCNT。
- 归属：WCNT/RCNT 在 L2 侧，调用级 watchdog 归 LIC，训练权重走 NI/SDN 不经 hub。
- 写口：单写口 32 B/拍，四核共享，有界等待，归 HUB-UP。
- HUB-ATT：三类合并键，9 个列表环，不碰 logits；HUB-SYNC 固定核序 FP32 合并、GO 后 1 拍生效、超时只上报。
- R-hub：16 lane、256 bit 条目、MXFP6 E2M3 + E8M0、25 B 载荷 + 16 bit 序号、入口 FIFO 与写 L2 路径分离、不检测序错位、MiniCPM 11.7 B/拍不作现行负载。
- 数据布局：L2 32 bank × 2048 深、每象限 512 KiB，残差 50 B/tile，列表头 8 B。
