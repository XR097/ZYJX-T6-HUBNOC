# 新旧 HUB / RHUB 结论差异（2026-11-07）

## 结论

新版文档已经改变模块边界。旧结论把 HUB 当成带 VC、信用、地址游标、完成计数和中心仲裁的协议处理单元，把 RHUB 当成独立的四路量化归约中心；这些内容不能继续作为当前 RTL 依据。

当前边界是：HUB 只做透明传输、H2C 多播分叉、H2C 两源 MUX、C2H 分流和控制道转发。MAE 搬运引擎给 H2C 逐拍地址、目的核掩码和源顺序；本核 CCU 给 C2H 逐拍地址和目标存储选择。写入完成由最终存储写入握手反馈给发令方，由发令方计数。

RHUB 的功能已经并入 MAE_CRU。MAE_CRU 由搬运指令选择，按 CRU 内地址的应到份数完成部分和、标量或读集合并；部分和结果 BF16 直出，经 H2C 数据网送出，不再采用旧 R-hub 的 VC2、pid/owner、组序号、MXFP6 g32 量化和 D-40 回送模型。

## 变化对照

| 主题 | 旧结论 | 新结论 | 处理 |
|---|---|---|---|
| 模块边界 | HUB 内含 DN/UP/ATT/SYNC，内部再拆大量协议叶子 | HUB 仅 H2C/C2H/控制道；CRU 属 MAE | 旧叶子树降为实现分解，不再写成 PDF 合同 |
| 数据格式 | flit、VC、`last`/`nw8`、信用池、无地址载荷 | `en/din/be/addr/src` 写流，ready 回流；控制道独立 64-bit 握手 | 删除旧字段和信用语义 |
| H2C 地址 | HUB 生成/累加地址、按段切分 | MAE 引擎逐拍给 L2 读地址和目的地址 | 地址主改归 MAE_ENG |
| H2C 多播 | HUB 多播缓冲、按目的信用跟踪 | 分叉点 + 每目的 1 位已取；各核独立 ready | 保留分叉容量和后端级数为参数 |
| H2C 两源 | HUB 仲裁 L2/RHUB 源 | MAE_ENG 按指令优先级给源顺序，HUB 只在单位边界切换 | 去掉 HUB 仲裁/老化 |
| C2H | HUB 汇聚并选择路由 | 每核 CCU 给目标存储选择；四路直通，不扇入 | 路由主归 CCU |
| 完成语义 | HUB 维护 WCNT/RCNT、返还信用后报告完成 | 最终存储写入回 `valid+src`，发令方计数 | 计数归发令方/CCU |
| RHUB/CRU | 四路 BF16 → MXFP6 g32，16/32 lane，pid/owner | MAE_CRU 按地址到齐合并，BF16 直出 | 旧 RHUB 结论标历史 |
| 拓扑时序 | 中心固定星形、固定状态机和 RTT | 各段流水级数、分叉位置、ready/回程可由后端调整 | A1-A7 纳入验收 |

## 旧问题闭环

- VC2/VC3 共享池限速冲突、D-40 中心/每核道数冲突、R-hub lane 图注冲突：已由新版写流和 MAE_CRU 边界取代；旧 OI-12/OI-13/OI-18 关闭并归档。
- R-hub owner、pid、量化精度和 VC2 回送问题：旧模型已退出当前架构；仅保留 MAE_CRU 的参与核、应到份数、地址范围和 BF16 精度验证。
- HUB-SYNC/ATT 的旧固定状态机、信用返还等待、HUB 内完成报告：新版明确由端点和发令方负责，旧时序 FSM 不再适用。
- 旧版关于 HUB 生成地址、维护环形回绕、解析载荷和报告完成的结论：均已删除。

## 新版仍未解决的问题

1. A1-A7 的每段流水级数、分叉位置、skid/FIFO 深度以及回程级数需要后端参数和随机化验收。
2. H2C 两源 MUX 的单位末拍边界、源顺序队列深度和 L2 busy 重发门限需要与 MAE_ENG 冻结。
3. 地址位宽、各存储对 `addr` 类位的解释、错误/复位极性和控制道队列深度仍需协议集成确认。
4. MAE_CRU 的 lane/FIFO 深度、合并流水延迟、BF16 累加精度、面积和高并发到齐行为需要标定。
5. C2H 写 L2 的核号-象限约束、H2C 写 L1 的多播握手归属、`src` 计数溢出和回程无 ready 的 CDC/时序假设需要验证。
6. 控制网与数据网不保证先后，长度转发晚于数据到达时的端点缓存和错误恢复策略需要补合同。

## 维护规则

当前文档若再次出现 VC、信用、`last/nw8`、HUB 地址游标、HUB 完成计数或独立 RHUB 量化归约，必须同时给出新版协议中的对应依据；否则视为历史内容。
