# 新旧 HUB / RHUB 结论审查（2026-11-08）

## 审查范围

本次工作区变动包含 16 篇正文 Markdown，以及 `_build`、图件、预览图和 `.pyc` 等生成物。架构判断以正文为准；生成物只检查是否随正文同步，不把二进制或缓存差异当作架构证据。

## 当前结论

11 月 8 日版本再次收窄并拆分了边界：HUB 组现在包含 `HUB_NOC` 和 `HUB_IDN`。`HUB_NOC` 连接中央 L2 与四核，`HUB_IDN` 连接 NI 的一路 32 B IDN 出口与四核。两者都只做带地址/控制的透明传输、多播分叉和写入握手汇总。

`HUB_NOC` 的 H2C 每道只有 L2 一个源，C2H 每核只有集成输出端口到 L2WP 一个去向；此前的 H2C 两源 MUX、C2H 到 MAE_CRU 的分流和 C2H 目标选择全部失效。C2H ready 低时由本核 CCU 门控计算，HUB 只传递反压。

`MAE_CRU` 不再连 HUB/HUB_IDN，也不再拥有由 C2H 写入的 CRU FIFO 或按地址到达表。各核先把数据写入 L2，MAE 通过 NI 读口按参与象限读取，收到各核发出报告后执行合并，再经 NI-L2C 写回 L2。归约和残差加是两条搬运指令；输入/输出编码由指令给出，包含 FP16、BF16、MXFP6、FP8 等组合，输出可为 BF16、FP16 或 MXFP6 稠密/按列表压缩。

变长对象从固定上限分槽改为实际长度紧挨存放，长度表独立存储。MAE 先搬长度表，再按表读取对象；搬运结束后以实际写入项数向目的 CCU 转发应写量。L1/L2 负责跨字节对齐和 bank 落位，HUB/MAE 不做字节移位。

## 旧结论状态

| 旧结论 | 状态 | 当前处理 |
|---|---|---|
| HUB 是透明传输，不生成地址、不维护完成计数 | 仍有效 | 扩展到 HUB_IDN |
| H2C 有 L2/MAE_CRU 两源 | 失效 | H2C 只有 L2 源 |
| C2H 按 L2/MAE_CRU 分流 | 失效 | C2H 只有集成输出端口→L2WP |
| C2H 由 CCU 给目标存储选择 | 失效 | CCU 在核内选择来源，HUB 只见单一路径 |
| RHUB 已由 MAE_CRU 取代 | 仍有效但需改写 | MAE_CRU 改为 L2↔L2、报告触发、多编码 |
| MAE_CRU BF16 直出 | 失效 | 编解码由搬运指令指定，支持多种输出 |
| MAE_CRU 按 CRU 内地址到达份数启动 | 失效 | 由 L2 四象限读和参与核发出报告启动 |
| HUB 组只有 HUB_NOC | 失效 | 新增独立 HUB_IDN |
| 变长对象按离线上限分槽 | 失效 | 紧挨存放 + 独立 token 长度表 |
| 固定 RTT/信用/VC/last/nw8 模型 | 仍是历史内容 | 当前正文继续采用地址+握手写流 |

## 旧问题闭环

旧 OI-12/OI-13/OI-18 仍属于历史模型，继续归档。旧 RHUB 的 owner、pid、组序号、MXFP6 g32 和 VC2 回送也不再驱动当前实现。

此前我们写下的“H2C 第二源”“C2H→CRU”“CRU 入口 FIFO/地址到齐表”“BF16 直出”结论已在本次审查中撤销，并同步改写 `hub_spec/`。

## 当前新增问题

1. HUB_IDN 的核集合必须与 `din/addr/seg/be/src` 同级流水到最后分叉点；旁带插级、分叉位置和回程汇总需要验证。
2. IDN 单路 32 B 上限下，MAE_DSU 的按字重排与 MAE_ENG 的核间轮排需要容量/吞吐边界。
3. C2H ready 低到 CCU 停算的传播深度、停算恢复和写入握手完成时刻需要周期验证。
4. MAE_CRU 四象限同址读在某象限 busy 时的对齐、掩码外象限不等待、发出报告收齐条件需要冻结。
5. MAE_CRU 多编码、内部精度、MXFP6 压缩和异常值语义需要参考模型及面积标定。
6. 归约→残差两条指令之间的 LIC 依赖和 Fusion-L3PU 分块循环需要端到端验证。
7. 紧挨对象、24-bit 长度表项（16-bit 字节数 + 8-bit tokmax）、先表后数据、搬完后应写量通知的顺序需要统一合同。
8. 协议正文的历史裁定段、图件和 `_build` 产物仍含旧术语，需要区分“历史记录”和“现行条款”。
