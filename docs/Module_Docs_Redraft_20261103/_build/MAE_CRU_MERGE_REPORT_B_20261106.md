## 6 待协调者

2. **NI_INT §5.6 MAE_CRU 写 L2 的带宽**：只写了"与其余来源同一阶段的并发写总需求由编译链排程"，引用的是 §2.3 已有的"同一阶段并发写总需求 ≤ 写集合口道数 × 32 B/拍｜编译链"那一行；CRU 输出的峰值与能否和 DDR 来源同时达峰没有依据，未写数。
3. **NI_INT §5.7 新增的 MAE_CRU 链路块实例参数**（256 bit，addr 24 + dest 1 + be 32）是照 MAE_DSU 那一行写的，没有单独依据，请确认。
4. **NI_INT §3.1 的 CRU 行**：只列经过 NI_INT 的三种（源 C2H 目的 L2、源 DDR、源 L2）；源 C2H 目的核 L1（经 HUB-DN）不经 NI，没有列。源 DDR / L2、目的核 L1 时 NI 只管把数据交 CRU，CRU → HUB-DN 一段不在本篇。
5. **MAE → LIC 完成通知的物理路径**：NI_INT §2.2 保留了"NI 控制道…不发完成消息"，按 ENG 目录 §2.2 理解为完成通知走 MAE_ENG 与 LIC 之间的口，不经 NI 控制道；如果集成篇另有安排，需要回改。
6. NI_EXT §2.3 "调用输出数据在前、状态字最后"的保证方从"MAE_ENG、LIC"改成了"LIC"（依据 ENG 目录 §12.2"都由 LIC 收到前一条的完成通知后再下发后一条表达"），请确认。
7. 本轮任务以外、各篇仍有"LIC 操作 15"（预取距离 / 缓冲轮转）引用，没有改动。
