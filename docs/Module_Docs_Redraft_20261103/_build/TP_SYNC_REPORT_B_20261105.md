## 4 与协议篇的矛盾与需要协议篇注意之处

1. **协议篇 §6.2 "L2 的写口同理，TREADY 恒高"** 与 L2 有两个写口共享单端口 bank 冲突（见 B-2）。
2. **协议篇 §3.3 / §3.6 的"固定 1 拍、无仲裁"只对 L1 成立**；L2 读口有 bank 仲裁（L2 §6，任务书要求保留），读时延只在无冲突时固定（见 B-3）。协议篇 §1.1 把核间数据网的端点只写到 L2 的写口与象限读口"→ HUB-DN 道"，读口这一段的信号未定义。
3. 协议篇 §7.4 完成表缺 NI ↔ L2 的两种搬运（见 B-4）。
4. 协议篇 §8.1 端点表缺 L2 的错误出口（见 B-6）。
5. 协议篇 §2.2 写"L2 同构：类位 = 象限号"，而 L1 的类有固定的 bank 集合与映射；L2 的"类"（象限）内部再分两堆，两堆的 bank 集合协议篇未定（本稿取 4 + 4，见 B-1）。

## 5 交给其他篇的事项

- **HUB 篇**：HUB-DN 道 n 发读的节奏（按发送 FIFO 余量、将满阈值含 $t_{\text{r}}$ 与冲突顺延）；收到 L2 读口"顺延"时保持重发；L2 错误出口若挂控制道，由 HUB 篇列端点。
- **MAE_NI_INT / MAE_NI_EXT**：NI 写 L2 逐拍 TUSER；NI 写口 TREADY 可能拉低一拍；NI ↔ L2 两种搬运的完成由 NI 报；PIN 尾部补整行。
- **MAE_ENG / ISA**：L2 区表与 LIC 操作 6 撤（V18-TP-14 已登记，ISA 会话处理）；搬运命令的 L2 地址 = [堆][象限][行号]。
- **数据组织篇**：L2 各类内容的对象划分、四道并行读的数据拆成四象限各一个对象。

### 7.4 新【待确认】

| # | 项 | 稿内位置 | 说明 / 建议 |
|---|---|---|---|
| B2-1 | **抢占优先级怎样随数据到达 L2 的集合器** | L2 §5.2 | 优先级写在搬运命令里（C2H 发送命令在 CCU、NI 写命令在 NI），但 L2 只见数据网的一拍（TUSER 19 bit 只有地址）。可选：TUSER 加 2–3 bit 优先级；或由发送方（L1 发送侧 / NI）把优先级放进入口 FIFO 的旁带。L2WP 的数据经 hub 扇入，hub 看不到 C2H 发送命令，所以 L2WP 方向只能随数据带。建议 TUSER 加优先级位，交协议篇与 ISA |
| B2-2 | **完成判据"末拍 + 固定时延"在集合器下只成立为上界** | L2 §5.2、§5.5、§6.3 | 有了入口 FIFO 与优先级，从接收桥成交到写进 bank 的拍数不再固定；执行方报完成必须用最坏值 $t_{\text{w}}$，这要求低优先级写者的等待有上界（老化或轮转）。若严格按优先级、无老化，低优先级写者可被无限推迟，C2H / NI 写的完成判据失效。建议集合器带老化，上界由设计者定并登记 |

### 7.5 与协议篇的矛盾

1. B2-3：协议篇 §2.2（L2 类位 = 象限号）与 §5.2（类位第 4 码 = CRU）在 C2H 上不能同时成立。
2. B2-2：协议篇 §7.4 的"末拍 + 固定流水时延"在 §6.2 的 L2 集合器下需改为"最坏时延"，并要求集合器等待有上界。
3. 协议篇 §6.2 只写 L2 集合器"先后按搬运命令里的抢占优先级"，未写优先级怎样到达 L2（B2-1）；也未写写道与读口撞 bank 时谁先（本稿默认写道先、可配【设计者定】）。
