## 1 改名（V18-TP-41）：核间信号与核内 RRAM 口同名

| 原名 | 新名 | 含义 |
|---|---|---|
| TVALID | **en** | 本拍有一次写 |
| TREADY | **ready** | 接收方本拍能收；核间比核内多的唯一一根线 |
| TDATA | **din** | 数据 |
| TKEEP | **be** | 字节写使能 |
| TUSER | **addr** | 目的存储字的逻辑地址 |
| TDEST | **dest** | 目的空间（0 = 存储，1 = CRU） |
| TLAST | （撤，见 §2） | — |

命令与标量网同样改：TVALID / TREADY / TDATA → en / ready / data（64 bit）；TLAST 撤，消息长度在首字（协议篇 §8.5 原本就写"消息长度由类型与首字决定"）。

**全文替换规则**：正文、表格、图注、脚本里的这些名字全部替换（包括 "TVALID ∧ TREADY 成交" → "en ∧ ready 成交"、"TUSER 24 bit" → "addr 24 bit"、"TKEEP 作为字节写使能" → "be 就是字节写使能" 等）；协议篇 §5.2 信号表改为新名并加一列"核内 RRAM 口对应信号"；§1.1 / §5 开头的"信号命名沿用 AXI 风格"改为"与核内 RRAM 口同名，核间只多 ready 与 dest"；§12 的"为什么"加一条（用户 11-06 原话）。**只在协议篇 §5.2 保留一张"旧名 ↔ 新名"对照表**（供读旧稿的人查），其他地方不再出现 T 前缀名字。AXI 对外口（NI_EXT 的 M0 / M1 / PIN）的 AXI 信号（AWADDR、WSTRB、RREADY、WLAST、BRESP …）是标准 AXI，不改。

## 2 撤 last（V18-TP-42）：链路上没有单位标记

**理由**（写进协议篇 §7.5 与 §12）：写入完成按写计数（§2.6），接收方不再数单位；IDN 送进 L1 的都是 32 B 对齐对象且"一个存储字由同一条道送全"，NWB 四拍必凑整字，没有需要末拍触发写出的尾字；紧密对象只经 NI 写口进 L2，每拍整宽带 be，接收桥逐拍写、不攒；合并点仲裁器与发令方（CCU、MAE 通道）同侧，"单位发完"是发令方内部信号；发出报告的单位数由发令方自己数；PIN 的 B 响应按 NI-L2C 仲裁器记的每笔事务拍数归属。

**改法**：
- 协议篇 §5.2 删 TLAST 行；§5.3.2 通用链路块旁带改为 addr 24 + dest 1 + be 32（数据网）、无旁带（命令网）；§5.5 / §6.2 NWB 不再有"TLAST 时写出"（改为"四拍凑满整字即写出；W / S 类一个存储字由同一条道送全，MAE 通道保证"）；§5.6.2 "只在 TLAST 处切换源" → "只在单位边界切换源；单位边界是发令方内部的信号（CCU / MAE 通道知道自己的单位何时发完），不上链路"；**§7.5 重写**为"搬运单位是发令方内部的粒度（发出报告的单位数、仲裁切换边界），链路上没有标记"；§7.3 图注与 `draw_transfer_protocol.py` 的 LENGTH-REPORT / STREAM-BEAT 删 TLAST 字样；§8.5 删 TLAST 行；§11 / §12 对应。
- L1 篇：§2.1 口表、§7.0 规则、§7.5 NWB（攒满整字即写；撤"TLAST 时写出"）、§8.2 发送桥（CCU 不再给 last）、§10 / §12 / §13 / §14 对应句；`draw_l1_arch.py` 标签。
- L2 篇：§2.1 / §5.1 / §5.2 口表删 TLAST、"L2 不据此做任何动作"句删；`draw_l2_arch.py`。
- VNU 五篇：接口表中 TUSER / TKEEP / TDEST / TLAST 字样按 §1 替换，TLAST 删。
- MAE_NI_EXT：§2.1 PIN 存储字行"一个 AXI 写事务对应一个搬运单位、末字打 TLAST" → "一个 AXI 写事务是 NI-L2C 仲裁器记账的一个单位（按拍数记），链路上无标记；事务的尾字在 AXI WLAST 时交出"（见 §3.6）；§7 同步。
- MAE_NI_INT：§2.1 / §3.2 / §3.3 / §5.3 / §5.5 / §5.7 实例表删 TLAST、改名；"NI 路径的 TLAST 由搬运引擎在最后一笔返回离开时打上"改为"搬运引擎数着该命令还有几笔没回，用于发送完成计数，不上链路"。
- MAE_IDN：§2 / §3 / §4.4 / §6 / §9 对应；`draw_mae_idn.py` 图注若有 TLAST 字样删。

## 3 六项补定（Agent 报告核出的空洞，依据与裁定如下）

| # | 项 | 裁定 | 写到哪 |
|---|---|---|---|
| 3.1 | PIN 的 B 响应归属：L2 的 NI 写口按象限分进不同入口 FIFO，各象限写进 bank 的先后可能与链路顺序不同，一个总写计数会误归属 | **写计数按（入链路, 象限）分别维护**（集合器本来就是每象限一个）；NI-L2C 仲裁器为每笔 PIN 事务记下"各象限各几项"，**四个象限的计数都到齐才回 B**。MAE 比对 L2 数据时同样按象限比对（V18-TP-43，细化 TP-37） | 协议篇 §2.6、§7.4.2；L2 §5.2 / §5.5；NI_INT §5.5；NI_EXT §7.6 |
| 3.2 | 长度转发与数据走两张时延无关的网，发出次序保证不了"先到达" | **数据可以先落地（接收方无状态、按 addr 写），长度转发只门控目的核 CCU 的消费与写计数比对**；协议篇 §8.7 "数据到达而对应配置未就绪 = 致命错误"只保留给"位点指令尚未装入 CCU"的情形，长度转发晚到不是错误（V18-TP-44） | 协议篇 §8.7、§10；NI_INT §3.4；L1 §7 |
| 3.3 | W / S 类一个存储字由一条 8 B 道送全时，32 B 读返回要拆成 4 拍，需要 4 × 32 B 的拆拍寄存器 | **拆拍寄存器放在 NI_INT 的读返回分路里**（每条道一个 32 B 寄存器，顺序交出 4 个 8 B），是结构性寄存器，不是入站缓冲；"不设入站缓冲"指不为吸收抖动设 FIFO | NI_INT §1.2、§3.3、§10 |
| 3.4 | 两源各自命令的链路分配不同时，交叉配置跟随谁 | **链路分配随单位走**：每个单位从它的发令方（MAE 通道）带来自己的核集合，MAE_IDN 在单位边界按当前单位的核集合配置交叉 | MAE_IDN §4.1 / §4.4 / §6 |
| 3.5 | 相邻命令能否重叠执行 | **允许**：后一条命令的请求可在前一条的返回未回完时发出；读请求记录按请求分路，同一链路保序，不同命令的返回按各自记录落位 | NI_INT §3.1 / §3.2 |
| 3.6 | PIN "有界时间内交出不满的尾字"的界值 | **尾字在 AXI 写事务的 WLAST 拍交出**（事务结束即交），不另设时间界 | NI_EXT §7.2 / §7.6 |
