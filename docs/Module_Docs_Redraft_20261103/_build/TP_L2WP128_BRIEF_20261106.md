## 1 新规则

### L2-03 L2 写侧 = 每核一条 32 B 写链路，HUB-UP 只分流

- **L2WP 由 1 条 32 B 口改为 4 条 32 B 写链路（每核一条，合计 128 B/拍），与读侧四象限读口（合计 128 B）对称。** 每个象限的写集合器有 5 个来源入口 FIFO：四核各一条 + NI 写口一条 → 4 条 bank 道（象限内一堆 4 个 bank）；撞 bank 由各自 FIFO 吸收，规则与 L1 集合器相同（逐项按优先级选）。优先级表：四核轮转、NI 写与四核的先后按 MAE 装的静态表（原 NI 写 vs L2WP 的表扩成 5 来源）。
- **HUB-UP 不再扇入、不仲裁**：四条 C2H 各自直通，hub 只按 dest 分流——dest = CRU 的拍交 CRU 入口，其余按 addr 的象限位送进对应象限集合器里**本核**的入口 FIFO。四核互不等待。
- **写计数按（源核链路, 象限）**：L2 每象限 5 个写计数（四核 + NI），MAE 按（源核, 象限）比对发出报告；R1（四核混计）不存在。TP-43 的"按（入链路, 象限）"不变，只是入链路多了。
- **TP-45 收窄**：删"HUB-UP 按拍仲裁"的表述；单位级仲裁只在发令方可见边界的合并点（C2H 口前、NI-L2C、MAE_IDN 两源、HUB-DN 两源）；L2 集合器逐项选。
- CRU 入口：四核 C2H 上 dest = CRU 的拍由 hub 分流到 CRU 入口 FIFO（每核一条或合并，【设计者定】），CRU 入口写计数同样按源核。

### L1-12 重组器选择位随读请求，撤"区"

- L1 §6.1a："由按区的配置位选择"改为：**每次读请求带 1 bit——直通（行字 / 训练块）或重组（列字区整段）——随位点指令里的读命令（CCU / RTR 给 L1 的 (列, pod 掩码) 列表）一起到 L1 的权重 lane 读口**；一个位点里行字区与列字区混读时逐请求切换，无位点级状态。
- L1 §2.3 补一句：W / S / A 三类只是硬件 bank 集合与口的接线（W 类 32 B 对齐、经固定 lane 到 pod；S 类尺度行；A 类激活类读口），**类里放什么由编译链的地址决定**——权重类可放任何 32 B 对齐、经 lane 读的数据，激活类可放非激活数据；L1 与 MAE 都不感知。

### CRU-01 超 32 B 的归约值分多拍

协议篇 §11 RIFT 行：撤【待确认】，改为"超 32 B 的一组（BF16 直出）占连续几个存储字、分多拍发，组序号在首字；字节编排在 HUB_CRU 篇"。

### TP-46 撤流式转发

协议篇 §7.3 第 4 条删除（"流式转发……不作默认，只在时延敏感位点用【设计者定】"）；改为一句："**对象必须写完才能发**：边写边发要求同一对象所在的 bank 同时读写（1R1W），L1 单端口 bank 不支持；流式效果只靠 ping-pong——写堆写、读堆发（§7.1）"。§12 加为什么（用户原话）。L1 篇若有"流式转发"字样同样删。

### NII-03 修订 WSU 无片外出口

MAE_NI_EXT §2.1 / MAE_NI_INT §2.1、§4.1、§5.4 / 协议篇 §5.1 链路表中"WSU 输出写片外 / 经 NI_EXT 去片外"的字样撤；WSU 出口只有 MAE_IDN（去 L1）与 NI-L2C 写客户（去 L2）。
