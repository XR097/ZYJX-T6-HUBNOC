## 1 改版后的核间协议（正式稿按此写）

全芯片三种总线不变：核内 **RRAM 口**（en / wea / be / addr / din / dout / vld，写当拍、读固定 1 拍、无握手，只在核内）；核间**带地址的握手写流**；**命令与标量网**（64 bit，不变）。信号名沿用 TVALID / TREADY / TDATA / TKEEP / TLAST / TUSER，新增 TDEST；正文**不再说"基于 AXI4-Stream"或"AXI4-Stream 子集"**，只说"带地址的握手写流（信号命名沿用 AXI 风格）"。命令与标量网同样不再说"64 bit AXI4-Stream"，写"64 bit 握手消息流"。

### 规则 1 链路：单向、点到点、一组信号，只差位宽

每拍信号：

| 信号 | 方向 | 位宽 | 含义 |
|---|---|---|---|
| TVALID | 发 → 收 | 1 | 本拍有效 |
| TREADY | 收 → 发 | 1 | 本拍可收；TVALID ∧ TREADY 成交 |
| TDATA | 发 → 收 | W | 数据，字节放在它在目的存储字里的位置 |
| TKEEP | 发 → 收 | W/8 | 有效字节；接收桥作为字节写使能 |
| TUSER | 发 → 收 | A | **本拍数据所在目的存储字的逻辑地址**（[堆 1][类 2][字节号 21]，以字节计），逐拍携带 |
| TLAST | 发 → 收 | 1 | 搬运单位末拍 |
| TDEST | 发 → 收 | D | **目的空间**：0 = L2、1 = CRU；由 MAE 的发送命令给出、随拍带，不折进地址 |

链路表：

| 链路 | 每核条数 | W | A | D | 目的 |
|---|---|---|---|---|---|
| H2C（hub → 核） | 4 | 32 B | 24 | 0 | 核 L1 |
| C2H（核 → hub） | 1 | 32 B | 24 | 1 | L2（TUSER = L2 逻辑地址）或 CRU（TUSER 低位 = CRU 条目号） |
| IDN（MAE_IDN → 核） | **4 条独立 8 B 链路** | 8 B | 24 | 0 | 核 L1；每条各自 TVALID / TREADY / TUSER / TKEEP / TLAST，不要求同拍 |
| NI → L2 写口 | 全芯片 1 | 32 B | 24 | 0 | L2 |
| L2 → NI（NI 返回读口之后） | 1 | 32 B | 按目的定 | 0 | NI_EXT 写出或 MAE_WSU 输入 |
| MAE_WSU 进 / 出 | 各 1 | 32 B | 24 | 0 | — |

撤：上行 TUSER 的 27 bit（目的 1 + 抢占优先级 2 + 24）→ TUSER 24 bit + TDEST 1 bit；**2 bit 抢占优先级取消**；"IDN 每核口 32 B、4 条 8 B 道经交叉按道掩码拆分、每核口每拍一个 TUSER"→ 4 条独立链路，每条链路接哪个核由 MAE_IDN 的交叉开关按命令配置（原"道掩码"改称"链路分配"）；核由链路标识不变。

### 规则 2 地址：每拍 TUSER 由 MAE 的 DMA 通道生成；核内由 CCU

- **MAE = 命令引擎 + DMA 通道。** 每条往链路送数据的物理链路配一条搬运引擎（C2H × 4、HUB-DN × 4、IDN × 4、NI → L2、L2 → NI、WSU 出口；CRU 输出作为 HUB-DN 道的第二个源进同一通道），搬运引擎只听 MAE 命令；搬运引擎的物理位置（MAE 中央或数据源旁）、一条搬运引擎内部的并行度（DDR 在飞请求数等）交设计者。
- 搬运引擎逐拍产生源地址与目的地址（TUSER）；线性段、gather、V 行字散写的行位交错、环形回绕都在搬运引擎内展开。**协议与执行方接口上不再有基址 / 步长 / 长度 / 环长**，它们只在 ISA 的搬运命令里作通道描述符。
- hub、L1 发送侧、NI_INT、MAE_IDN、MAE_WSU 自己没有寻址逻辑。接收方无状态：按 TUSER 类位的固定映射落 bank、按 TKEEP 写字节。
- **核边界两侧各一个主**：核内 RRAM 口的每拍地址由本核 CCU 算；跨核边界的每拍地址由 MAE 通道算；CCU 对核外搬运只能触发或报长度，不能定目的地址。L1 的发送桥与接收桥是 MAE 通道在核内的落脚点，不归 CCU。
- 协议篇 §2.4 拆成两段：核内"CCU：地址 = 基址 + 累加"（保留原文与图 FIG-TP-ADDR-ACCUM，图题改为核内例）；核间"MAE 搬运引擎逐拍给出"。

### 规则 3 握手与时延无关；skid 强制；同步域；无 burst

- 每拍 TVALID ∧ TREADY 成交；TREADY 为 0 时发送方保持。
- **强制条款（V18-TP-32）**：核间链路的每一个流水级和每一个端点，TVALID、TDATA、TUSER、TKEEP、TLAST、TDEST、TREADY 全部为寄存器输出，相邻级之间不得有组合路径；每级配 skid 缓冲，深度 = 从本级拉低 TREADY 到上游真正停发之间的在途拍数（单级寄存器为 1 格）；将满阈值 = 深度 − 在途拍数。适用：hub 中心与四条 HUB-DN 道发端、HUB-UP 扇入、MAE_IDN 交叉与四条链路、各核 L1 接收桥（LDP、NWB）与发送桥、L2 的 NI 写口与 L2WP 集合器入口、CRU 入出口、WSU 进出口、NI-L2C 两方向。验收：随机化每条链路的流水级数与 TREADY 拉低时序，逐位一致、不丢拍、不重复。
- 任意位置插任意级寄存器功能不变；**功能定义里不出现任何固定拍数**。
- 核间链路同一时钟域，不考虑跨时钟域（对外 AXI 口的跨域在 NI_EXT，不变）。
- 无 burst、无响应、无 outstanding：地址随数据同拍走，源是 SRAM，接收方自带地址，burst 的三项收益都不存在；DDR 突发在 M0 口不变。

### 规则 4 多播：发送侧共享缓冲、各目的独立取走

发送侧（HUB-DN 道、MAE_IDN）把一拍放进自己的缓冲，为每个目的核各保留一个读指针，各核按自己的 TREADY 分别取走，全部取走才释放；**不再"等齐后同拍成交"**。四核物理同构，多播用同一个 TUSER、落同一位置（用户认可）。缓冲深度【设计者定】。

### 规则 5 单位与完成：收发两端按指令数据量计数，无完成消息、无标签

- TLAST 划出搬运单位，只有两个用途：接收方数单位；紧密对象最后一个不满的存储字见 TLAST 即带字节写使能写出（NWB 另在 TUSER 换存储字时写出当前攒字寄存器）。
- **发送侧**：MAE 搬运引擎按指令给的数据量数自己发出的拍（变长对象的实际长度由长度报告填进命令），数到即"发送完成"，不含任何时延常数。通道物理上远离 MAE 核心时，"发送完成"经命令与标量网回一条短消息【设计者定】。
- **接收侧**：每个接收方对每条入链路数"到达的单位数"（TLAST 成交次数），并给出"集合器 FIFO 与攒字寄存器已排空"信号，交本地发读方比对指令里的应收数——L1 交本核 CCU（CCU 从位点指令与长度转发得应收数，比对通过且排空后才报位点完成 / 切堆）；L2 与 CRU 的到达计数器交 MAE（本地计数器，MAE 发依赖该数据的读命令前比对）；DDR 以 AXI 写响应为准（NI_EXT 交 MAE）。
- **撤**：协议篇 §7.4 "末拍成交 + 固定流水时延即已落地"、"完成由执行搬运命令的一方报"、§8.1 的"完成：hub / NI / L1 → MAE，末拍 + 固定时延"消息行、L2 篇的 $t_w$、L1 篇 §8.5 发送侧报完成；"接收方不发任何应答"的意思保留（没有逐单位消息）。LIC 的屏障 = 各核 CCU 位点完成事件（已含到达比对）+ MAE 的发送计数。
- **NI 路径的 TLAST**：DDR 不同 AXI ID 的返回可能乱序，搬运引擎数着该命令还有几笔没回，最后一笔离开通道的那拍打 TLAST，不重排。
- 链路上**没有单位标签、没有请求号**；接收方报告不带命令号。

### 规则 6 交错与仲裁：同一目的不交错，不同目的可交错；TDEST = CRU 优先

- **同一目的的单位在一条链路上不交错**：合并点的仲裁只在 TLAST 处切换源，一个单位的各拍连续（各拍地址不要求连续）。**目的不同（TDEST 不同）的拍可以交错**：C2H 上 AEB 直达口的部分和可插在 L1 发送侧正在发的单位中间（11-05 "直达口优先、有拍就先走"保留）。
- 合并点的归属：把几个源合到一条链路的仲裁器记单位的先后（NI-L2C 记 M0 / M1 / PIN / WSU，HUB-UP 记四核，HUB-DN 记 L2 读出与 CRU），接收方只计数；"第 $k$ 个到达的单位是谁的"由仲裁器的记录给出，用于 PIN 的 B 响应等需要按源归属的场合。
- 仲裁规则：HUB-UP 扇入与 hub 内分流按 TDEST = CRU 优先、其余轮转；L2 每象限集合器里 NI 写与 L2WP 的先后按一张**由 MAE 装的静态优先级表**（PIN 的外设写等待上界靠它）；L1 集合器按 CCU 装的静态表（不变，落地来源最高）。原"抢占优先级随 C2H 的 TUSER 到达、NI 写方向由 NI 从命令取"撤。

### 规则 7 格式：链路不带数据类型

保留 §1.1"每种总线只有一种格式，不按数据类型分形态"。类型与精度在指令（每种指令格式的"数据流载荷类别 4 bit / 元素位宽 3 bit / 分组大小 2 bit"字段，以及 MXU 输入激活格式码、量化点目标格式码、K 存储精度码、布局码）与对象头（§9.3 类型字段）；写到哪类空间由 TUSER 类位。K hi 两种落地形态由 MAE 发两份地址（两次写）实现，接收方不识别类型。

### 规则 8 读返回与片外口

- **M0 / M1 读返回**：NI 对每笔读请求记下 (去向, 目的逻辑地址)，返回数据按请求对应关系分路上链路（去 MAE_IDN、MAE_WSU、NI-L2C、LIC、NI_EXT 写通道）；对应关系怎样维持（用几个 AXI ID、队列多深、放在 MAE_ENG 还是 NI_INT）由设计者定。不写"目的标签"格式。
- **PIN（V18-NIE-02）**：每种片外输入在 L2 的落点按（调用种类, 输入种类）由编译链固定，外部主方往固定窗口写；并行到达时两个固定窗口按调用奇偶轮换，也是静态的。**撤运行期窗口配置**（CIF 外设窗口寄存器逐次配置、MAE 的 PIN 窗口收回 / 释放命令）；窗口基址与长度上限是初始化装一次的常量表或地址译码常量。运行期只剩"写完了、实际多长"，由调用描述符与 CIF 门铃给出（已有机制）。不变：超窗 → SLVERR；任意字节起点与长度（V18-TP-25）；B 响应以 L2 到达为准（NI-L2C 仲裁器记先后 + L2 到达计数）；外设写等待上界【设计者定】。
- NI_INT 不做错误检查（V18-NII-05）；NI_EXT 的 AXI 主口错误经 NI 端点转报 LIC（转发，保留）。

### 规则 9 MAE 组五单元

MAE 组 = MAE_ENG、NI_EXT、NI_INT、MAE_IDN、MAE_WSU（V18-NII-03 / 04）。NI_INT 只剩读返回分路、NI-L2C、NI 控制道端点；MAE_IDN = 4 条独立 8 B 链路 + 交叉开关 + 多播缓冲；MAE_WSU 可从 DDR 或 L2 取数、输出到 L1（经 MAE_IDN）/ L2 / 片外。正式稿凡写"NI_INT 的道 $i$ → 核 $i$""IDN 接收桥（NI_INT）"处改为 MAE_IDN；凡写 WSU 在 NI_INT 内处改为 MAE_WSU。
