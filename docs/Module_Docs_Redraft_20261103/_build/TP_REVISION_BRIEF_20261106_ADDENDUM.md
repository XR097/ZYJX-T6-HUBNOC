## 1 四条新规则

### TP-35 C2H 由各核 CCU 发令；原则改为"谁拥有源，谁发令"

- 源在核内（L1 的任何对象、AEB 部分和）的搬运由本核 CCU 发令：CCU 按位点指令取目的（L2 逻辑地址或 CRU 条目号）、TDEST、长度或"按对象实际长度"，发读 L1 的 en / addr，并逐拍给出 TUSER / TDEST / TLAST；**发送桥是 CCU 的 C2H 通道**。源在核外（DDR、L2、WSU、CRU）的搬运由 MAE 发令，不变。
- 撤"MAE 的 C2H 发送命令"、撤"长度待报"往返（MAE 发带待报的命令 → CCU 报长度 → MAE 填命令 → 启动）。改为：**CCU 发完一个对象后，经命令与标量网向 MAE 发"发出报告"（对象标识、单位数、总存储字数、记录数、尾字有效字节）**，MAE 之后经 H2C 读该对象或转发长度给目的核时用它。原"对象长度报告"消息改名"发出报告"，字段相同加单位数。
- 昨晚协议篇 §2.4.2 / §6.1 把 C2H 通道写成 MAE 的、L1 篇 §8.2 写成 CCU 发读但 TUSER 由 MAE 搬运引擎给，两处统一为本条。
- "核外的数据搬运都由 MAE 发令"的原则改为："**源在核外的搬运由 MAE 发令，源在核内的由本核 CCU 发令；搬运途中按固定规则的合并（CRU）由 MAE 配置**"。
- MAE 对 L2 里"这份数据到了没有"的判断：L2 写计数（TP-37）+ 发出报告里的单位数。

### TP-36 单位级仲裁，任何链路上单位永不交错

- 撤昨晚"目的不同（TDEST 不同）的拍可以交错"的例外。**所有合并点只在 TLAST 处切换源，一个单位的各拍连续**（地址不要求连续）。
- C2H 口前的两源合并（L1 发送侧、AEB 直达口）：两源同时有数据时 **AEB 直达口在单位边界优先**，L1 发送侧阻塞到当前单位的 TLAST；都在 CCU 的域里，CCU 可在排程上让位图先于部分和发出。原 11-05"直达口有拍就先走、L1 发送侧让出该拍"撤。
- 依据：K 切分 attention 按 tile 流水时，tile $t$ 的 AEB 部分和与 tile $t+1$ 的读集位图重叠，目的都是 CRU；两种单位都只有几十拍。

### TP-37 统一的"写入完成"判据：写计数在写进 bank 时加一，核内核间同一条

写进协议篇 §2 共同约定（新小节），§3.2、§5、§7 引用：

> **写入完成 = 写入口出口的写计数达到发写方的应写量。** 每个写入口维护一个写计数——核内：写集合器的每个写者各一个；核间：每条入链路的接收桥各一个（L1 的 4 条 H2C + 4 条 IDN、L2 的 L2WP 与 NI 写口、CRU 入口）——**在存储字真正写进 bank（或 CRU 条目）的那一拍加一**；发写方按指令知道应写量，由本地控制方比对：核内写者由本核 CCU 比对，核间链路由目的核 CCU（L1，应收量来自位点指令或长度转发）或 MAE（L2 / CRU，应收量来自命令或发出报告）比对。计数达到即可切堆、发 GO 或发读；**不设排空信号，不依赖任何固定时延**。计数按位点或按对象清零【设计者定】。

- 这是 PandaChip NCC 的做法（主控数发出量、接收 cache 只自增写指针 `wr_fms_cache_addr`）加一步比对；核内也适用，因为集合器 FIFO 里排队的写并未写进 bank，§7.1 的"写堆写完成"由此有了判据。
- 撤昨晚的"到达单位计数 + 集合器排空信号"写法；撤 L2 篇"到达计数器交 MAE 本地计数器"中的"排空"。单位（TLAST）仍保留：紧密对象尾字写出、仲裁切换边界、发出报告里的单位数。

### TP-38 通用链路块（Common Link Block），skid 可配，数据网与命令网共用

写进协议篇 §5.3（取代"寄存器输出 + skid 强制"一小节的写法，要求不变、形式变为块）：

> **通用链路块**是核间所有握手链路的唯一构件：一级 valid / ready 握手流水，参数化——数据位宽 $W$、旁带位宽 $S$（地址、TDEST、TLAST 等折进旁带）、**skid 深度**（= 本块拉低 ready 到上游真正停发之间的在途拍数，单级为 1）、流水级数；所有输出寄存器化，相邻块之间无组合路径；验收随机化全部参数与 TREADY 时序。**数据网（$W$ = 256 bit，旁带 = TUSER 24 + TDEST 1 + TLAST 1 + TKEEP 32）与命令与标量网（$W$ = 64 bit，旁带 = TLAST 1）都用同一个块例化。** hub 的四条下行道、HUB-UP 扇入、hub 控制道，MAE_IDN 的四条链路与交叉，各核收发桥，NI-L2C 两方向，NI 控制道，都是它的实例加各自的仲裁器或多播缓冲。

- HUB 篇的要求因此写成"通用链路块实例 + 仲裁器 + 多播缓冲"，传数据、传命令、传发出报告只是参数不同。
- 命令与标量网的链路由此也获得 skid 条款（昨晚只写了数据网）。
