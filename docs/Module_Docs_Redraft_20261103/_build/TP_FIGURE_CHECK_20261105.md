## 0 脚本自检（每次生成都跑，四张图最终都是 0 项）

`Fig.save()` 在写 SVG 前检查以下几项，任一项不过就打印并以非零码退出：

1. 文字与标签不出画布、彼此不重叠；
2. 文字与标签不压任何连线（按线段与文字框求交，外扩 1.5 px）；
3. 标签不跨色块边框；
4. 连线不穿过任何色块内部（虚线分组框不算色块）；
5. 不同连线不共线重叠；
6. 横线与竖线的不相连交叉自动画跳线弧（默认横线跳；横线标 `hop=False` 时改由竖线跳），交叉点离拐角太近也报错。T 形接点（多播分叉）不算交叉，画实心圆点。

## 5 发现的矛盾与需主会话决定的点（未改正文）

1. **接收桥写口的地址来源**：正文 §3.4"L1 的每一次读写，en 与 addr 都由本核 CCU 发出"、任务书图 B"CCU → L1 的 en / wea / addr（所有口）"，与 §5.4 / §6.2"接收方按 TUSER 落 bank、不累加、不记状态"不一致。图 B 按 §5.4 画：LDP / NWB 写口的 addr = TUSER、en 来自成交拍，CCU 不参与。
2. **发送源与 C2H 的合路**：§6.1 只列两个发送源（L1 发送侧、AEB → C2H 直达口，各带桥），§4.2 stall_tx 又说"传给直写发送桥的推送源"，§4.3 表有"出口级 / VNU → 发送桥"。另外 §1.1 规定每核只有 1 条 C2H，两个 Stream 主口如何合到一条 C2H（按拍仲裁？谁优先？）没有写。图 B 画成发送桥接收 L1 发送侧读口与出口级 / VNU 直写，AEB 桥另出一路，两路在核边界前汇成一条 C2H（圆点）。
3. **CRU 出口走哪张网**：任务书 #6 写"CRU → HUB-DN（RSP / GO），控制网（V1.8）"；V18-TP-07 的控制网清单只列"交 CRU 的标量"，没有说 CRU 的归约值（V1.7_3 HUB_NOC §1.2：MXFP6 g32 一组 25 B + 16 bit 组序号）回核走控制网还是 H2C。图 A 按任务书画成 CRU ⇄ hub 控制道。
4. **CIF ↔ LIC 是否属于控制网**：任务书 #14 归为控制网（图 A、D 用橙虚线）；正文 §8.1 末句"致命错误从 LIC 出 M55 的口在 CIF，不在本网"。若 CIF ↔ LIC 不算控制网，图中两线应改为灰色。
