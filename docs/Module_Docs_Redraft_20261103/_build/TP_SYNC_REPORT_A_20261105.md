## 3 新提出的【待确认】

1. **A 类连续行轮流落 4 个激活类口**（L1 §2.3、§4.4）：协议篇 §2.2 的 A 类线性映射让相邻行落 bank 8、9、10、11，而口 $p$ 只接 bank $8+p$；"pod $p$ 的激活记录缓冲 ↔ 口 $p$"不再成立。(a) L1 外选择器做成 4 口 × 客户交叉、CCU 逐拍定去向；(b) 编译链按 $n_{\text{bank}}$ 行步长分配只走一个口的数据流。归 CCU 篇 / L1 集成篇。
2. **W1 部分改配时 A 类 bank 列表**（§4.1）：整组改配参考 (8, 9, 10, 11, 4, 5, 6, 7)；只改配部分 bank 时怎样排。
3. **重放旁路**（§7.1）：H2C 激活经 LDP 段片解析直交 pod、不落 bank 的通路在协议篇无对应（接收桥只写 L1、TREADY 恒高、无区分字段）。撤旁路（落 A 类后由 CCU 读给 pod）或另定区分与反压。
4. **RIFT 的去向**（§7.3）：CRU 归约值按组序号对回（token, 列块）移出 L1 后归 CCU / NLU 还是 MAE。
5. **落地写与核内写撞 bank 写侧**（§7.4）：落地写到达拍不由 CCU 排、TREADY 恒高当拍必写，可能与另一道落地写或核内写撞同一单端口宏。(a) 编译链保证每 bank 写侧位点内只属一个写入方（例如 H2C 第 $n$ 道按步长只落 bank $8+n$）；(b) 接收桥前加缓冲、允许拉低 TREADY（与协议篇不符）。
6. **按列到达的权重落地**（§7.6）：V18-L1-01 的 NWB 16 B 分拍写入依赖半行写，与 32 B 整行最小写冲突。(a) NWB 暂存一整列（约 $K/2$ B）拼整行；(b) DDR 改按列对深度优先存放（MAE）。COLARRIVE 图与表待改法定后重画。
7. **NWB 暂存将满时怎样让 NI 减速**（§7.6）：接收桥 TREADY 恒高，原"经 IDN 链路信用反压"已撤。
8. **发送命令的源字段怎样交给 CCU**（§8.2）：协议篇 §4.2 / §3.4 让 CCU 发发送侧读的 en / addr，而 §8.1 发送命令只到 L1 命令单元；由 L1 命令单元转给 CCU，还是 CCU 从本核指令自取。
9. **发送命令是否带源环长**（§8.1）：协议篇 §2.4 只写 CCU、hub、NI 取环长。
10. **"数据到达而配置未就绪"在 L1 的具体情形**（§11）：L1 无可装载配置，是否把"落地数据的类位指向本位点已改配走的 bank"算作此类。
