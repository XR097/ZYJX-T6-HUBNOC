## 4 与协议篇的矛盾或协议篇未写清处（供主会话维护协议篇时参考）

1. **IDN 每核物理宽度**：§1.1 表写"1 道 8 B（整拍给一核时 32 B）"，§5.1 又写"道 $i$ 固定接核 $i$"。若每核物理上只有一条 8 B 道，"4 道都给它"做不到。同一份数据投多个核的 IDN 多播也没写（P12）。
2. **C2H 合并后的分流**：§6.1 定了口前合并，但 §5.2 的五信号里没有区分"写 L2"与"交 CRU"的手段，归约属主号也无处放（H6）。
3. **§8.1 端点表缺行**：没有 MAE → CCU（列表到齐）、核间位图 / 判决的消息路径（MA15、H7）。
4. **§7.1 与 ISA 的衔接**：只说"运行期靠写完成与最后读者完成事件推进"，没有说 LIC 操作 15 按份累计这些事件的计数器在谁那里（MA4）。
5. **整行写的边界情形**：§2.1 / §9.1 定了 L1 / L2 最小写 32 B 整行，但没有覆盖三类天然不满行的写：PIN 的 WSTRB 写（X9）、V 行字按 8 B 散写（P13）、稀疏列尺度行（NI P8）。
6. **H2C 直达 MXU 的激活入口**：协议篇 §1.1 口表与 §6.2 只有"接收桥挂 L1"，而 11-04 D15 的 MXU 有"H2C 激活入口"（MXU P8）。
7. **协议篇自身不一致（小）**：§8.6 图 FIG-TP-CTRL-MSG 的图注仍写"写进槽 1（槽 0 正在执行）"，是已作废的"两槽"写法；§8.2 已改为"两个指令寄存器 + Fusion-CCU 段 SRAM"。
8. **命名易混**：协议篇的"LIC 操作 15"（块数、预取距离、缓冲轮转）与 MAE 目录 §4.11 的"MAE 操作 15"（入站分发与整形配置）是两条不同的操作。本组目录里凡涉及发送许可都写全"LIC 操作 15"。
9. **V1.8 内部（不属协议篇）**：V18-TP-03 / 05 / 13 正文仍写"区号 6 + 行号 16""MAE 按区资源计数"，已由 TP-14 / TP-08 的 11-05 段取代。本组按协议篇写，未改 V1.8。

## 5 对 CCU 篇的新需求

CCU_CTL 与 CCU_INTEGRATION 的目录稿尚未产出：核对时 `Final_Architecture/` 下只有 CCU_RTR 目录。下面 16 条已逐条写进 `V17_3_MODULE_TOC_CCU_RTR_20261103.md` 文末一节，写这两篇目录时采用；哪条落 CTL、哪条落 INTEGRATION，随两篇目录一并定。

1. **地址推理恒在 CCU**：核内发起的每次 L1 读写由 CCU 发 en / wea / addr，dout 去向（pod $p$ / VNU 入口 $i$）由 CCU 定；产出单元只给 din 与长度；接收桥落地写例外（协议篇 §3.4）。
2. **地址 = 基址 + 字节累加**：步长默认 32 B、可配；高位行号给 L1、低 5 bit 偏移给解包器；每对象重置；回绕 base + $(k \bmod L)$ 由 CCU 做；越类边界为致命错误（§2.4）。
3. **按对象头解码记录位置**：写入时逐记录累加长度得（行, 偏移）；跨行记录读两次；不设偏移表（§9.3–§9.4）。
4. **权重驻留下每 token 一个写累加器**（$T$ 个定长 token 槽）；token 驻留下一个累加器（§9.7）。
5. **整行统计判决位点清单**：按 SEL 选择模式逐位点列出哪些位点在权重驻留下须先存 BF16 再压紧，给出暂存空间与二次读顺序（§9.7，用户 11-05）。
6. **dout 去向与激活类口时隙**：含 L1 发送侧读 L1 占用的时隙（§3.4、§6.1）。
7. **stall 入口清单**：stall_mxu[0…3]、stall_vnu[$i$]、stall_tx，各自停发对应读 en；CCU 不看余量、自身不拉 stall、无核级 stall（§4）。
8. **指令端点**：当前 / 下一条两个 1,024 bit 指令寄存器 + Fusion-CCU 段 SRAM（段计数器按 LIC 操作 15 块数本地循环）+ 短消息 RF 队列；Fusion-L3PU 只在 LIC；"两槽 SRAM"作废（§8.2–§8.3）。
9. **对象长度报告**：对象结束指令提交时发 MAE（对象标识、总行数、记录数、尾行字节），不回读；同核自产自用的不报（§7.3）。
10. **收长度转发**：来自 hub（H2C）或 NI（IDN），先于数据；未就绪而数据到达为致命错误（§7.3、§8.7）。
11. **堆位切换条件** = 写完成 ∧ 最后读者完成，体现在下一位点地址的堆位；L1 的 TLAST 计数交 CCU；撤角色位命令（§7.1、§7.6）。
12. **撤按空间计数**：只发最后读者完成等事件交 LIC（§7.1）。
13. **事件与错误出口**：CCU → LIC 走命令与标量网（§8.1、§10）。
14. **标量**：CRU 合并值经命令与标量网回 CCU / VNU 寄存器，不落 L1（§8.1）。
15. **散写**：每道 token 在 A 类连续分配，L1 不解析记录头（§9.5）。
16. **Router 读序列到 bank 地址**：（列对, pod 掩码）换算成 [堆位][W][行号]，同拍带 pod 掩码、段位位、半段位（L1 正式稿 §6.1）。

此外，本组其他目录对 CCU 提出的、目前还挂在【待确认】上的需求：发位点完成事件的时点（HUB_CRU C8）、LIC 操作 15 计数的归属（MAE MA4）、核间位图消息的发起（HUB H7）。（11-05 晚三项均已裁定，见 §6.3。）

### 6.5 对 CCU 篇的新需求（本轮追加与改写）

已写进 `V17_3_MODULE_TOC_CCU_RTR_20261103.md` 文末一节。

**改写的条目（记录级对齐）：**
- 第 1 条：核内写者经本类写集合器的自己那条 FIFO 写。
- 第 2 条：地址只到存储字，字计数 $r$；回绕的 $L$ 也可来自发送命令的源环长。
- 第 3 条：按对象头推每条记录的首字号 $r_{i+1} = r_i + \lceil n_i/32 \rceil$；没有字内偏移，也没有跨字两次读。
- 第 4 条：token 槽长见第 20 条。
- 第 9 条：长度报告按存储字计。
- 第 13 条：致命错误加"槽超上限"。
- 第 16 条：lane 读口 8 道。

**追加的条目：**

17. **写集合器优先级表装载**：每类一张，随位点命令装。默认落地 LDP > NWB > 核内写者，同优先级轮转。A 类 4 / 8 bank 时表格式不变。
18. **读侧排撞**：4 个激活类读口共用 A 类 bank，同拍撞 bank 由 CCU 错开，读仍固定 1 拍。
19. **bump 分配器**：顺序产出的对象，下一基址 = 上一对象结束字号，不预留上限。
20. **token 槽上限计算**：
    - 有封顶：$k$ + 强制入选数。
    - 不封顶：全保留记录长度 2,648 B（hidden 2,560）。
    - LOSS 参与词号列表：两组 TOPK 的 $k$ 之和。
    - 槽长按存储字取整；超上限为致命错误。
21. **RIFT 对回**：32 B 内由 CCU 地址推算。
22. **C2H 发送命令进 CCU 命令队列**：命令带源环长与抢占优先级，CCU 发读；AEB 部分和与跨核 OR 位图用 CRU 类码。
23. **收 MAE 的列表到齐计数短消息**。
24. **"配置未就绪"的定义**：位点指令未装入 CCU 时有落地写到达。
25. **并发写约束**：≤ 道数 × 32 B/拍由编译链保证；CCU 给出的写者节拍与优先级表须与之一致。
