另有一项【设计者定】值得用户知道：**权重驻留下 QNT 需要每个在写 token 槽一个未满行的缓冲**（VNU_QNT §3.7、§9.1）。L1 只能整行写、而相邻到达的段属于不同 token，QNT 必须为每个 token 槽攒满 32 B 才写，约 $T \times 32$ B（$T = 128$ 时 4 KB）。协议篇 §9.7 只说"CCU 每 token 一个写累加器"，没有提这块缓冲。

## 4 与协议篇的矛盾

1. ~~K 末组重量化~~ **已定、协议篇已改（11-05 晚）**：协议篇 §9.2 改为 K / V 一个 key 一槽、按存储 tile 分、没有沿 key 方向的重量化（V18-QNT-05），与 QNT 正文一致。原文：协议篇 §9.2 第 ② 档写"K 的末组在补齐到 32 个 key 时重做该组量化"，FIG-TP-SLOT-COUNT 画成"K 平面对象按 32 个 key 一组存槽，追加到第 32 个 key 时该组重量化"。现行 K 格式（MXINT8 g32）是**每个 key 沿 head_dim 每 32 维一组**（VNU_QNT §3.2），追加 key 不改动已有组的尺度；V18-QNT-05 已把"沿 token 成组"的预研格式与"未满组追加重量化"退役。两处说法冲突，正文按 V18-QNT-05 未加重量化，请主会话裁定协议篇是否改为"只补槽、不重量化"，或说明此处"组"指存储 tile。
