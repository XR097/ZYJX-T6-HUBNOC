# NPU 数据组织格式易读版：数据在各级存储中怎么摆

## 这份文档解决什么问题

这份文档不是算法说明，而是“一个数据从 DDR 走到计算阵列时，具体落在哪一级存储、以多少 bit 保存、什么时候改变格式”的说明。

读它时可以一直问三个问题：

1. 数据现在在哪一级存储？
2. 当前一个传输单位有多大、如何对齐？
3. 下一次格式变化由哪个模块完成？

## 先建立存储层次

```text
DDR / 共享 SRAM
        ↓ MAE 读请求
NI 入站 FIFO / NI 写缓冲
        ↓ SDN 或 NI-L2C
中央 L2（2 MiB，32 bank，4 象限）
        ↓ HUB-DN / L2 读引擎
各核 L1（WB 288 KiB + AB 160 KiB）
        ↓ MXU_FEED / VNU
pod 内 RF、段环、行片环、E6/F1b 状态库
```

### 术语解释

- **DDR**：片外大容量存储，容量 16 GB。计算核没有直接 DDR 口，访问由 MAE 发起。
- **MAE**：存储访问引擎，负责产生 DDR/共享内存请求。
- **NI**：网络接口，负责把外部读回的数据送到相应核、L2 或训练缓冲。
- **SDN**：面向多个核的数据分发网络，可按 8 B 通道拆分或多播。
- **L2**：全芯片共享 SRAM，2 MiB，由 32 个 32 B 宽 bank 组成；每 8 个 bank 组成一个 512 KiB 象限。
- **L1**：每个计算核私有的片上 SRAM。WB 存权重，AB 存激活、残差、列表和状态。
- **WB/AB**：Weight Buffer / Activation Buffer，即权重缓冲和激活缓冲。
- **pod**：核内更小的计算存储单元，包含 RF、段环、行片环等。
- **E8M0**：8 bit 指数尺度，只保存指数，不保存尾数；多个低 bit 数据共享一个 E8M0。
- **MXFP6**：每个元素 6 bit、每 32 个元素共享一个 E8M0 的浮点压缩格式。

## 各级存储的硬件关注点

### DDR 与共享内存

DDR 有效访问以 64 B 为基本单元，AXI 每次传 32 B，同一个 64 B 单元的两次访问要连续发出。M0 入流上限约 19.2 B/拍；共享内存 M1 每方向约 0.8 B/拍。

DDR 中每种数据使用自己的布局编号，MAE 根据布局编号生成地址。RTL 设计时不要在链路层猜地址格式，地址由 MAE 模板和命令层提供。

### NI 入站路径

数据先进入站 FIFO：M0 FIFO 不小于 16 KB，M1 FIFO 约 4 KB。之后根据目的标签进入：

- SDN：总带宽 32 B/拍，可把一个 32 B 拆成四个 8 B 通道，或同时多播给多个核。
- 每核 NI 写缓冲约 1 KB，是 WB 权重和 K/V 的主要写入口。
- KRR 负责 K 的解码、旋转和再量化。
- V 展开负责 V 的低位展开和尺度修正。
- WSH 负责训练权重的形态重排、转置和尺度组织。

### 中央 L2

L2 由 32 个 bank 组成，bank 宽 32 B、深度 2048；每 8 个 bank 是一个象限。象限与 D-40 的道固定连接，因此一个 token 写入哪个象限，会影响后续由哪条 D-40 道读出。

L2 不是简单的“固定区域 + chunk 区”。它是一个由分区表按模型、调用类型和位点动态分配的池，可能存放 token chunk、KV、部分和溢出、Verify 常驻数据、输入区以及列表环。

### 每核 L1 与 pod

每核 L1 约 448 KiB：WB 约 288 KiB，AB 约 160 KiB。WB 的基本写入单位为 136 bit，由两个 68 bit bank 拼成；每个 bank 含 8 B 数字和 4 bit 尺度（合计 32 个 4 bit 码 + E8M0）。AB 常按 8 B 字和 32 B 行组织。

pod 内还有：

- E6 出口队列：保存 16×BF16 条目，供 R-hub 或后处理使用。
- F1b 状态库：保存尚未完成归约的定点中间结果。
- S-T 行片环：保存训练或行主序权重的消费形态。
- I 模式段环：保存按段广播的权重和激活。

## 权重的两种主要布局

### 列字布局

列字布局适合输入轴稀疏的权重，例如 q/k/v、o、down 的部分平面和某些 gate/up 平面。基本路径是：

```text
DDR 列字单元
  = 前置尺度 + 按输入列排列的数字
        ↓
SDN 按 8 B 通道拆给四个核
        ↓
NI 写入 WB bank，并把 E8M0 填入尺度字段
        ↓
段读口 / pod 段环
```

一个实际 1 KB 列字单元前置 64 B E8M0。每列数字由四个核各拿一个 8 B 通道组成 32 B。SDN 做的是整 8 B 通道拆分，不是任意 bit 级重排。

### 行主序布局

行主序布局适合沿输出通道逐行访问的权重，例如 up hi、gate/up lo 以及部分 LM Head 副本。DDR 中数字按行保存，尺度放在单独的行尺度向量平面；每行有 `K/32` 个 E8M0。

NI 落地时，把第 `s` 个 K 组的数字和尺度组成一个行字，映射到：

```text
bank_pair = (输出行号 m + K 组号 s) mod bank_pair_count
地址      = s
```

这个对角 skew 映射的目的，是让整段读、单行读和训练窗口读尽量落在不同 bank 对，避免同拍冲突。读出后，出口旋转器把 skew 顺序恢复成计算阵列需要的顺序。

## 激活和残差

### 紧凑 MXFP6 激活记录

一个 token 的激活按每 32 个通道切段。每段包含：

1. E8M0 尺度。
2. 32 bit keep 位图，表示哪些通道保留。
3. F 标志位，表示保留通道的额外状态。
4. 保留元素的 6 bit MXFP6 数值。

段内只补到字节边界，整条记录末尾才补齐到 8 B。记录本身在 L2 chunk 池中按 token 位置写入象限，HUB-DN 再按段交错重放给各核。核侧段解析器根据段头的 keep 位图推断段长度，不能只依赖链路层的字节有效位。

### 残差

残差 tile 采用纯 MXFP6，不单独给大数保留 BF16 旁路。每 64 通道 tile 为 48 B 数值 + 2 B E8M0，共 50 B，tile 之间连续排列。

残差加法在 BF16 中完成：先还原输入残差和 BF16 输出，再相加，最后一次量化回残差格式。未完成归约的部分和仍以 BF16 存在本核 L1，不能提前量化成 MXFP6。

## KV 数据

KV 有 POST 和 PRE 两种格式：

- **POST**：RoPE 后量化。K hi 每 key 约 68 B，V 按 MXINT8 g128 或 4 bit g128 保存。
- **PRE**：RoPE 前量化。K 拆成高 2 bit 和低 2 bit 两个平面；V 为 4 bit 平面。高平面用于粗算，低平面在录取后 gather。

无论 DDR 使用 POST 还是 PRE，进入 WB 后都统一为 K 的 MX 4+4 形态，这样 WB 和 MXU 不必感知 DDR 的两种来源格式。

V 的入站过程主要是按 key 和列位做 8 B 粒度散写；它是地址重排，不是任意 bit 级转置。I 模式读一整段时，每个块只取属于自己的列位。

## 部分和、梯度与训练状态

F1b 每个“输出行 × 驻留 token”约有 40 bit 定点状态。K 归约未完成时，部分和以 BF16 RNE 写入本核 L1；下一段开始时按同一个 `Ebase` 装回 F1b。

R-hub 接口的入口条目是 16×BF16=256 bit；四路头部对齐后固定顺序相加，再把两条结果拼成 32 元素 MXFP6 g32 返回属主核。

反传梯度默认使用 MXFP6 E2M3 g32；少数位点可指定 MXFP8 E4M3 单遍格式。dK/dV 的跨 chunk 累加区使用 BF16，按 `[layer][kv_head][key][K/V]` 等价地址组织。

训练权重的 LoRA 副本使用 MXINT8 g32；优化器状态通常是 FP32，也可选择 Q0.15 残差平面。它们与同组权重使用相同的布局、分组和顺序。

## 列表、位图和调用记录

列表环记录由 8 B 头和可变载荷组成。头中包括模板号、序号、格式位和计数；格式位决定载荷是位图还是 3 B 行号列表。

- 录取位图：每个 64-key tile 使用 64 bit；多个核的位图逐 bit OR。
- 区块位图：一位代表一个 KV 区块，区块并集由 HUB-ATT 计算。
- Verify 树记录：每槽 32 bit，包含词号、父槽号、TAG 和 VALID。
- 父槽表：128×7 bit=112 B。
- 节点档表：占用槽数 + 每槽 2 bit 的状态，最大约 33 B。
- 祖先掩码：按 query 组和 key 组切成 32×32 bit 块，每块 128 B。
- Proposal 输出：每个位置的词号用 3 B，概率用 2 B，按位置和概率顺序排列。

列表写入通常经过上行 VC1 和 L2 单写口；写完成计数由 L2 侧维护，MAE 在满足计数条件后才能读取。

## 读 RTL 时建议重点看什么

1. 每个存储的“自然写入单位”是多少：8 B、32 B、136 bit、50 B 还是 544 B。
2. 尺度 E8M0 和数值是否同一平面，谁负责合并。
3. 地址是连续递增、bank skew、列位散写还是环形游标。
4. 一个记录的边界由长度字段、keep 位图还是 `last` 决定。
5. 格式转换在哪一级发生，链路层是否只是搬运。
6. 写完成/读完成计数属于哪一级资源。

## 当前规格中的冲突和未定项

这份专项文档明确列出了多处尚未冻结的内容，包括：

- I 模式段在 WB bank 上的列字与尺度映射。
- 行主序尺度是内嵌还是独立平面，以及 S 行 gather 如何取得尺度。
- PRE 模式 K 高平面在 L2 中的具体排布。
- K lo 行字和 S8 块的尺度字段由谁填充。
- WSH 转置写暂存的 bank 几何。
- MXFP6 位序、keep 位序和空段 E8M0 的取值。
- F1b 40 bit 定点格式的最低位和截断方式。
- 列表头位序、载荷字节序、区块列表格式和容量。
- 梯度组轴、MXFP8 例外范围和训练状态容量。

这些问题在进入 RTL 前必须逐项指定 owner、冻结版本和验证方式。当前不要根据本文件自行猜测 bit 位序或 bank 映射。
