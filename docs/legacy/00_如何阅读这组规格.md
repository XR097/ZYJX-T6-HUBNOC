# 这组规格到底在描述什么

这四份文档描述的是 NPU 里一组“把数据送到正确位置，并在核之间做少量合并”的硬件。它们不是算法说明，也不是可以直接综合的 RTL 设计。

最重要的整体关系是：

```text
中央 L2 SRAM
    │
    ├── HUB-DN ──> CC0 / CC1 / CC2 / CC3
    │                 │
    │                 └── 各核产生结果后经上行链路返回
    │
    └<── HUB-UP <── CC0 / CC1 / CC2 / CC3
             │
             ├──> L2 单写口
             ├──> HUB-ATT   位图/列表/广播
             ├──> HUB-SYNC  标量/barrier
             └──> R-hub    K 切分部分和
```

- **计算核（CC，Compute Core）**：真正做矩阵乘、向量运算和 attention 的四个核。
- **中央 L2**：四个核共享的片上 SRAM。文档给出的组织是 32 个 bank、4 个象限。
- **HUB NoC**：连接 L2 和四个核的集中式互连。NoC 是 Network-on-Chip 的缩写，意思是片上网络。
- **R-hub**：挂在 HUB 中心的专用归约单元，只处理 K 维切分产生的部分和。
- **HUB-ATT**：处理 attention 相关的位图、列表和广播。
- **HUB-SYNC**：处理标量合并、barrier 和控制同步。

## 先把几个容易混淆的词分开

- **数据搬运**：把一段数据从源端送到目的端，不改变数据含义。HUB-DN、HUB-UP 主要做这件事。
- **归约（reduction）**：把多个来源的同一结果相加、求最大值或做其他合并。R-hub 做固定顺序的 BF16 加法。
- **多播（multicast）**：一份 flit 同时送给多个核。发送方要为每个目的核扣信用。
- **VC（Virtual Channel，虚通道）**：同一条物理链路上的逻辑队列，用来隔离重放、数据、响应和控制流量。
- **信用（credit）**：接收端告诉发送端自己还有多少空槽。没有信用时，发送端必须停发。
- **flit**：链路一次发送的固定大小数据单元。本项目的 HUB-核间 flit 是 32 B。
- **位点（site）**：一次有明确输入、输出和同步边界的计算阶段。一个矩阵乘或一个 attention 阶段可以对应一个位点。
- **GO**：位点配置完成后的启动事件。GO 之后，位点控制在约定的时钟边界生效。
- **barrier**：等待一组参与者都完成后再继续的同步点。
- **SFD（Stream Format Descriptor）**：流格式描述，说明数据元素宽度、组大小、尺度位置、长度来源等。
- **末拍 `last`**：表示当前拍是一个传输单位的最后一拍。
- **有效字数 `nw8`**：末拍中有多少个 8 B 字有效。它不是逐字节有效掩码。

## 阅读时要持续问自己的五个问题

1. 数据从哪个队列出来？
2. 目的端是哪一个核、哪一个 bank 或哪一个功能单元？
3. 谁负责产生地址或写游标？
4. 什么条件下允许发送，什么条件下必须反压？
5. 什么时候算“这一条记录已经完成”？

如果一段规格没有回答这五个问题，就把它记到待确认清单里，不要直接凭感觉写 RTL。
