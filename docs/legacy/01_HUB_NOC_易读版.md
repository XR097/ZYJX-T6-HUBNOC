# HUB NoC 易读版

> 这是一份给数字 IC 前端工程师的工程说明。它把原始需求按“先懂用途，再看接口，最后看条款”的顺序重排。
> 文中的带宽、VC、信用和完成条件仍以 V1.5 规格为准；如果本说明与原始规格冲突，以协议规格和项目最新裁定为准。

## 先用一句话理解它

HUB NoC 是“以中央 L2 为中心的两级集中式互连”。四个计算核 CC0～CC3 之间没有直连，数据要经过 HUB 才能互相到达。HUB 主要做三件事：

1. 把中央 L2 里的数据送给一个或多个计算核。
2. 把四个计算核产生的数据汇总后写回 L2，或送到 R-hub、HUB-ATT、HUB-SYNC。
3. 在中心完成跨核必须共享的位图合并、列表写入、结果广播、标量合并和位点同步。

它是互连和同步模块，不是计算模块。HUB 不做 DDR 访问、TOPK 选择、阈值判定、采样，也不把普通数据重新量化。K 维部分和的加法由单独的 R-hub 完成。

## 先认识几个名词

- **NoC（Network on Chip）**：片上网络。这里指 HUB 中心到四个计算核之间的数据通路和流控逻辑。
- **L2**：中央共享 SRAM。HUB 从这里读数据，也通过单写口把核的结果写回这里。
- **计算核/CC**：四个并行计算单元，编号 CC0、CC1、CC2、CC3。
- **flit**：HUB 链路上的基本传输单位。一个 flit 是 32 B（byte，字节）。
- **道（lane/channel）**：D-40 下行的独立 32 B 通路。共有 4 道，每道绑定一个 L2 象限。
- **VC（Virtual Channel，虚通道）**：逻辑上独立的流。不同 VC 有各自的队列和信用，避免一种流把另一种流完全堵住。
- **信用（credit）**：接收方告诉发送方“我还可以接收多少个 flit”。没有信用时发送方必须停发，防止 FIFO 溢出。
- **SFD（Stream Format Description，流格式描述）**：描述一条数据流的格式、元素位宽、组大小、长度来源等信息。HUB 的普通链路只搬运字，不解析 SFD 对应的数据内容。
- **位点（point）**：一次矩阵乘或一次阶段性计算。位点之间用 barrier（栅栏）切换。
- **barrier**：位点同步点。参与核都完成当前位点后，HUB 才广播 GO，下一位点才开始。
- **tile**：一块固定大小的数据块。attention 的位图和区块列表通常以 tile 为单位处理。
- **OR 合并**：把多个核送来的位图按位或，得到所有核的并集。

## 片上拓扑

HUB 采用“中央 L2 + 两级分发”的结构：

```text
                         ┌──────────────┐
                         │   LIC/MAE    │
                         └──────┬───────┘
                                │ 配置/事件
┌─────────┐       ┌─────────────▼─────────────┐       ┌─────────┐
│  L2     │◄─────►│ HUB 中心                   │◄─────►│ CC0     │
│ 32 bank │       │ HUB-DN / HUB-UP            │       └─────────┘
│4 象限   │       │ HUB-ATT / HUB-SYNC / R-hub │       ┌─────────┐
└─────────┘       └─────────────┬─────────────┘◄─────►│ CC1     │
                                │                      └─────────┘
                                ├────────────────────► CC2
                                └────────────────────► CC3
```

这里的“第一级”在中心，包括 L2 象限读引擎、上行汇合、L2 单写口、HUB-ATT、HUB-SYNC 和 R-hub；“第二级”是 4 个道发端，把每道的 flit 按目的掩码送给四个核。

### 外部主要接口

| 接口 | 方向 | 作用 | 主要参数 |
|---|---|---|---|
| D-40 | HUB → 四核 | 下发重放数据、K/V、残差、响应和控制 | HUB_NOC 的拓扑表述为中心共享 4 道 × 32 B/拍 = 128 B/拍；协议摘要另有“每核 4 道”文字，复制数量以架构裁定为准 |
| 上行链路 | 四核 → HUB | 送回区域数据、列表、位图、标量和部分和 | 每核 32 B/拍 |
| 单写口 | HUB-UP/HUB-ATT → L2 | 把上行数据写入 L2 区域或列表环 | 四核共享，32 B/拍 |
| R-hub 接口 | HUB-UP ↔ R-hub | 传输 K 切分的 BF16 部分和 | 上行 VC2；R-hub 输出走 D-40 VC2 |
| LIC 控制口 | LIC ↔ HUB-SYNC/HUB-DN | 下发位点描述符、GO，回报合并结果和超时 | 控制消息 |
| MAE 事件口 | MAE ↔ HUB | 计数门限、读写完成和资源事件 | 控制/事件消息 |

训练权重当前不经过 HUB-DN，而是由 NI 通过 SDN 直接多播到训练核。SDN 是相关协议接口，但不应把训练权重通路算进 HUB-DN 的数据职责。

## 链路上的基本格式

### D-40 下行头

每个 32 B flit 附带 12 bit 侧带头：

```text
目的掩码 4 bit | VC 2 bit | 类别 3 bit | last 1 bit | nw8 2 bit
```

- **目的掩码**：`0001`～`1000` 表示单播，`1111` 表示四核多播。
- **last**：本传输单位是否在本 flit 结束。
- **nw8**：本拍有多少个 8 B 字有效；非末拍恒为满 4 个字。
- D-40 不带地址。核侧落地口根据本地位点描述符、区域基址和游标生成写地址。

### 上行头

每个上行 flit 附带 14 bit 侧带头：

```text
VC 2 bit | 类别 3 bit | last 1 bit | nw8 2 bit |
归约属主号 2 bit | 区域号 4 bit
```

上行也不带地址。HUB-UP 根据“核 + 区域”的配置维护写游标。区域号在列表环写入时表示列表环编号。

### 四个 VC 的用途

#### 下行 VC

| VC | 名称 | 常见类别 |
|---|---|---|
| VC0 | 重放/灌入 | 激活段片重放、同流灌入 |
| VC1 | 数据 | K/V、残差/特征行、AB 直写、部分和读回、Draft 分布 |
| VC2 | 响应 | R-hub 归约值、HUB-SYNC 标量回送 |
| VC3 | 控制 | 控制消息、描述符和判决广播 |

控制 VC 源端严格优先，保证 GO、描述符和错误事件不会被普通数据长期堵住。重放 VC 使用 `wD` 保底窗口；VC2 与数据 VC 共用该保底槽，不单设数据槽。`wD` 为描述符中的 4 bit 参数（0～8），`capdown=128-4*wD`。

#### 上行 VC

| VC | 名称 | 常见类别 |
|---|---|---|
| VC0 | 窄口/结果 | 录取位图、区块位图、lo 读集、K 切分判决、标量 |
| VC1 | 数据 | 区域写、列表环写 |
| VC2 | 部分和 | 发往 R-hub 的 BF16 部分和 |
| VC3 | 控制 | 位点完成、释放事件、资源事件 |

## 信用和完成条件

信用是这套 NoC 的核心。发送方不能简单地“看到 valid 就发”，必须确认接收方还有空间。

- 下行 VC0/VC1 的信用按“核、VC、道”分别管理；上行每核只有一条链路，信用按“核、VC”管理。某个下行道停住时，不应挡住其他道。
- VC2/VC3 的信用按“核、VC”使用共享池。HUB_NOC 写作每个共享 VC 每拍最多 1 个 flit，协议汇总写作 VC2+VC3 合计每拍 1 个；限速模式见未决项台账，不能自行选择。
- 初始信用等于接收端落地 FIFO 深度。
- 信用通过与链路同束的单拍脉冲返还。
- 下行每核有 10 根信用返还线：VC0/VC1 各 4 道，VC2/VC3 各 1 根；上行每核 4 根，每个 VC 1 根。
- 建议的上行入口深度：VC0 4 flit、VC1 12 flit、VC3 2 flit；VC2 使用 R-hub 入口 FIFO，16 条只作参考默认值，实际深度待 RTT 仿真冻结。

### 两种“完成”不要混淆

1. **链路信用完成**：表示接收 FIFO 有空间，解决的是“会不会溢出”。
2. **资源完成**：表示一个区域、列表或读写单位真的完成，解决的是“什么时候可以复用槽位或开始下一步”。

写完成计数器 WCNT 和读完成计数器 RCNT 放在 L2 侧，不放在 HUB-SYNC 中：

- 写完成：单位最后一个 32 B 行真正落入 L2 bank。
- 读完成：末标记 flit 发出后，所有目的核的信用都已返还。
- barrier 不能代替 WCNT/RCNT；区域交接必须看对应计数器。

## 四个子模块分别做什么

### HUB-DN：下行分发

HUB-DN 从 L2、R-hub、HUB-ATT、HUB-SYNC、LIC 和 MAE 接收数据，然后发往四个核。

每个 D-40 道大致包含：

1. 一个 L2 象限读引擎。
2. 若干 token 游标，维护不同重放流的位置。
3. 段片切分逻辑，根据 SFD 和元素位宽决定每段占多少字节。
4. VC 仲裁和信用检查。
5. 多播目的计数器。

### HUB-DN 的调度规则

- 控制 VC 严格优先。
- 重放 VC 使用描述符 `wD` 保底窗口；VC2 响应与数据 VC 共用该保底槽，控制 VC 仍严格优先。
- 不为超口带宽自动降档；`w=8` 时允许约 120→143 B/拍的超口需求，链路按信用自然停顿，违例由核侧计数、HUB 按位点汇总。
- 一个读单位的末 flit 只有在所有目的核都返还信用后，才向 L2 侧报告 RCNT 完成。
- 同一流内保持发送顺序；不同流可以交错。

### HUB-UP：上行汇合和单写口

HUB-UP 接收四个核各自的 4 个 VC 源队列，按 VC 和类别分流：

```text
上行 VC1 区域数据 ───────► L2 单写口
上行 VC1 列表/结果 ──────► HUB-ATT ─► 列表环/广播
上行 VC0 位图/判决 ──────► HUB-ATT
上行 VC0 标量 ────────────► HUB-SYNC
上行 VC3 事件 ─────────────► 按类型分流：SYNC / NI-SDN / MAE / LIC / 档表同步
上行 VC2 部分和 ─────────► R-hub
```

HUB-UP 的关键点：

- 上行 flit 没有地址。
- 写地址由“核 + 区域”的基址、长度和回绕游标产生。
- 同一区域内，写入顺序等于到达顺序。
- 四核共享一个 32 B/拍单写口，必须有界等待，不能有某一类流永久独占。
- L2 的 WCNT 由 L2 写仲裁在真正落 bank 时更新。

### HUB-ATT：位图、列表和广播

HUB-ATT 只处理跨核需要合并或广播的轻量信息，不承载逐列评分、粗 logits 或完整 logits。

主要功能：

- 收齐 attention 录取位图后按位 OR。
- 收齐区块位图后按位 OR，从同一并集记录并行产生区块列表环写请求和参与核广播。
- 多核训练时合并 lo 读集位图。
- 按环号把各核的列表记录和结果记录送入 L2 单写口。
- 把 Prefill 阶段的 K 切分判决结果按参与核掩码经 VC3 广播；该消息不是位图 OR，也不进入 L2。

典型合并键如下：

| 数据 | 合并键 | 合并结果 |
|---|---|---|
| 录取位图 | 层、KV 头、64-key tile | 64 bit 位图 OR |
| 区块位图 | 层、KV 头、查询波次 | 可配置宽度，最多约 512 bit |
| lo 读集 | 位点、列块 | 位图 OR |
| K 切分判决 | 列号 | 属主核产生的每列 2 bit 结果，按参与核转发 |

HUB-ATT 不做 TOPK、不做阈值判定，也不处理 logits 本身。TOPK 选择在 LM Head 属主核完成，HUB 只搬运列表和结果记录。

### HUB-SYNC：标量和控制同步

HUB-SYNC 负责三类事情：

1. **标量合并**：按 token、轮次标签和参与核掩码配对，按固定核顺序做 FP32 合并。
2. **位点 barrier**：收集各核的位点完成事件，达到期望数量后发送 GO。
3. **barrier 超时**：超过门限后向 LIC 报错；调用级 watchdog 仍由 LIC 负责。

标量合并的结果通过 D-40 VC2 回到核侧标量抽头。不同标量的合并规则由数据流约定，例如求和、最大值或在线 softmax 状态合并。固定核序是行为要求；FP32 合并误差目标 `2^-20/2^-12` 仍为【待标定】项。

### Barrier 的简单时序

```text
CC0 完成 ─┐
CC1 完成 ─┼─> HUB-SYNC 检查位点号和参与掩码
CC2 完成 ─┤
CC3 完成 ─┘
                 │ 全部到齐
                 ▼
          下行 VC3 广播 GO
                 │
           GO 后 1 拍生效
```

参与核没有全部到齐时，不能提前发 GO。位点号不匹配时应产生错误事件。

## 列表环和 L2 写入

L2 中有固定区域的环形列表，当前需求涉及 9 类列表，包括录取并集、lo 读集、TOPK 列补算、接受路径、键号、重算、掩码镜像、区块列表和 S 列表。

列表写入必须经过单写口。每个环需要维护：

- 当前写指针。
- 环长度和回绕规则。
- 环满标志。
- 写入记录的有效条数。
- 与 L2 WCNT 的完成配合。

环满时，HUB-ATT 必须反压写者；不能覆盖尚未被 MAE 消费的记录。

## 六种调用中 HUB 的角色

### Prefill

- q/k/v/o 激活通过 D-40 多播重放。
- gate/up 可能使用 K 切分，部分和经过 R-hub。
- attention 录取位图和区块位图经过 HUB-ATT 合并。
- 层入口标量经过 HUB-SYNC 合并。
- 每层大约有 5 个位点 barrier。

### Decode

主要是单核或单节点退化场景，重点验证单播重放、信用和控制通路。

### Proposal

主要由 CC0 工作；训练开启时会有列表和梯度范数相关的跨核通信。训练权重仍由 NI/SDN 直达训练核。

### Verify

- 调用开始时分发节点档表、祖先掩码、父槽表、Batch 行表、Draft 分布和随机数。
- attention 可能由 2～3 个核参与。
- 录取位图、区块位图和列表记录经过 HUB-ATT。
- 调用内档表修改需要通过控制同步。

### Target 独立训练

训练状态和 OPT 写回经过单写口，训练权重由 SDN 直达，不占用 D-40。

以下仅是 RTL 实现分解建议，不改变 PDF 所定义的四个 HUB 子单元边界，也不把叶子名视为已冻结合同：

```text

  ├─ dn_l2_read_engine[4]
  ├─ dn_stream_cursor_segmenter
  ├─ dn_vc_scheduler
  ├─ dn_credit_tracker
  ├─ dn_multicast_tracker
  └─ dn_lane_tx[4]

hub_up
  ├─ up_ingress_fifo[4][VC0..VC3]
  ├─ up_vc_class_router
  ├─ up_write_cursor

  └─ up_credit_return

hub_att
  ├─ accept_bitmap_merge
  ├─ block_bitmap_merge
  ├─ lo_readset_merge
  ├─ list_ring_writer
  └─ decision_broadcast

hub_sync
  ├─ scalar_pair_table
  ├─ scalar_merge
```

实现顺序建议为：先做链路字段和信用计数，再做 HUB-UP 单写口，再做 HUB-DN 调度，最后接入 HUB-ATT、HUB-SYNC 和 R-hub。

## 最小验证闭环

### 链路和信用

- 没有信用时不能发送。
- FIFO 满时发送端能停住，且不会丢 flit。
- 信用返还只增加对应 VC/道的计数。
- `last` 和 `nw8` 只在合法范围出现。
- 同一流保持顺序。

### HUB-DN

- 单播：一个目的核收到完整单位。
- 多播：四个目的核都收到相同顺序的数据。
- 一个目的核阻塞时，其他允许的流和道仍可工作。
- 只有所有目的信用返还后才增加 RCNT。
- 控制 VC 可以抢占，但数据 VC 仍满足最低份额。

### HUB-UP

- 四核同时写时，单写口不丢数据。
- 同一区域写顺序与到达顺序一致。
- 游标正确回绕。
- 列表环满后正确反压。
- VC0/VC1/VC2/VC3 分流不串路。

### HUB-ATT/HUB-SYNC

- 位图必须收齐参与核后才 OR。
- OR 结果只广播给参与核。
- barrier 位点号错误会报错。
- 缺核时最终不会错误发 GO。
- 标量在不同到达顺序和回压下，结果按固定核顺序保持一致。
- barrier 超时能上报 LIC。

### 系统场景

至少准备三个场景：

1. Qwen Prefill 的激活多播 + K 切分 + R-hub 回送。
2. Verify 的 2～3 核 attention 位图 OR 和区块列表广播。
3. 单核 Decode 的最小单播路径。

## 当前已知的未定项

这些内容在原规格中仍标为待审查、待仿真或待标定，不能擅自当成最终 RTL 参数：

- 区块位图的记录格式和 OR 粒度编码。
- D-40、上行和 SDN 的实际往返时延及落地 FIFO 深度。
- 上行 chunk 池按 token 定位时的偏移索引对齐。
- S 列表环的记录格式和长度。
- Batch 前缀 tile/私有 tile 的段号位宽及参与核掩码派生方式。
- 调用内档表修改同步的时延预算。
- 区块并集广播到 CTL 的时延。
- MiniCPM 上行 VC2 负载的历史口径。
- 门数、RF 容量和宏观面积账的最终核算。
- 训练窗口释放事件对 D-40 份额的影响。
