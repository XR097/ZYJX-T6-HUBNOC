# HUB_NOC、HUB_IDN 与 MAE_CRU 验证计划

本计划只验证 `docs/specs/` 已冻结的行为，不新增端口、错误状态或运行时检查。接口冲突先回填[问题台账](../reviews/open_issues_current.md)，不能用测试结果替规格拍板。

## 1 启动顺序

| 优先级 | 内容 | 退出条件 |
|---|---|---|
| P0 | 端口方向/宽度、H2C↔象限、C2H↔象限、IDN 32 B、CRU 参与掩码 | 端口矩阵与正式篇逐项一致 |
| P1 | back-to-back、随机 `ready`、多播慢核、C2H `stall_tx`、IDN 逐字旁带、复位 | 不丢、不重、不串，反压恢复后保序 |
| P2 | CRU 参考模型、压缩/keep、先表后数据、归约→残差依赖 | 逐位/吞吐/完成计数结果达到正式篇口径 |

N-04、N-18 和 V18-01…V18-12 关闭前，不得把对应行为写成固定断言；可用参数化用例暴露差异。

## 2 HUB 数据通路

- H2C 四道分别绑定四个 L2 象限；目的核掩码在单位内保持，分叉后每个目的独立 `ready`，慢核只在其余量耗尽时反压。
- C2H 核 n 只写象限 n；下游 `ready` 低时验证发送 FIFO/`stall_tx` 门控和恢复，不产生虚假握手。
- 连续可接收时每拍一个 32 B 字；随机插入寄存器/skid 只增加延迟，不改变数据和旁带配对。
- 命令网按 `en/ready/addr/data` 逐拍传输；字段宽度和端点队列深度使用 N-04 参数。

## 3 HUB_IDN

- 每个 32 B 输入字携带独立 4 bit 核集合，与 `addr/seg/be/src` 同拍；到核链路不携带集合。
- 覆盖单播、双播、四播、核集合每字切换、任意目的反压和回程 `src` 计数。

## 4 MAE_CRU

- 四路独立 ready/返回先后：只等待参与象限，结果与到达次序无关。
- 参考模型覆盖逐元素、FP32 标量、读集按位并和压缩输出，检查固定象限次序及格式。
- 结果写回区分 CRU 交出、目的 L2 写入握手计满和 LIC 完成通知三个时刻。
- 归约→残差两条指令覆盖 LIC 依赖；N-18 决定报告触发后再冻结定长合并用例。

## 5 变长对象、复位和统计

- 覆盖元数据项、E8M0、F 列表、码块的先后，跨字写和应写量晚到；应写量按 N-19 的写入拍口径计数。
- 复位清除在途数据、分叉已取位、合并状态和待发通知，不产生虚假 `valid`/完成。
- 记录每条链的吞吐、`ready` 低拍、分支等待、写入握手、实际字节数和完成时刻。

## 6 测试记录模板
