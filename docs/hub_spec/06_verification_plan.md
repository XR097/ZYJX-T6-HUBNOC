# HUB_NOC、HUB_IDN 与 MAE_CRU 验证计划

> 适用版本：2026-11-08。验证依据为 HUB_NOC、HUB_IDN、MAE_CRU、MAE_ENG 及传输协议的现行条款；本计划不新增硬件错误检查或状态。

## 1 接口与结构

- 从正文生成端口矩阵，检查 `din` 32 B、`be`、24 bit `addr`、`seg`、`src`、正向 `en`、读返回 `vld`、ready 和反向写入握手的方向、宽度及旁带同拍关系。C2H 回程是不带号的写入有效脉冲，H2C/IDN 回程带 `src`（HUB_NOC §2.1、§7；HUB_IDN §2）。
- 检查 HUB_NOC：H2C 道 n 只连接 L2 象限 n；C2H 核 n 只连接 L2WP 象限 n；H2C 每道只有 L2 源，C2H 每核只有集成输出端口来源。
- 检查 HUB_IDN：一路 32 B 输入、四核各一路 32 B 输出；每个存储字的 4 bit 核集合与数据、地址、`be`、`src` 同级流水到最后分叉点。
- 随机化每段寄存器/skid、分叉位置、回程级数和 FIFO 深度，确认插级只增加延迟，不改变数据或握手归属。

## 2 HUB 多播、反压与完成

- 覆盖单播、双播和四播；每个目的 ready 独立变化。分叉点对未取目的拉高 `en`，`en` 不依赖 ready；全部目的取走后可接下一拍。慢目的在分支容量内不阻塞快目的，分支满后才反压上游（HUB_NOC §5.2；HUB_IDN §5）。
- H2C 核掩码来自单位的指令参数，单位内保持一致，并随每拍数据/地址流水到分叉点；不同单位在单位边界切换。HUB_IDN 的核集合随每个存储字给出，可按字改变。分别验证两者与 `addr/seg/be/src` 不串拍；到核链路不携带核集合（MAE_ENG §3.2、§7.1；HUB_NOC §3.3；HUB_IDN §4.1）。
- C2H 下游 ready 低时，反压传到集成输出端口，按正文的发送 FIFO/stall_tx 机制门控 CCU；恢复后不丢字、不重放、不提前完成。验证四核互不等待及核 n 只写象限 n（传输协议 §7.1；HUB_NOC §6）。
- 所有目的可接收时，HUB_IDN 支持连续每拍一个 32 B 输入字；用 back-to-back 测试确认已取位更新、接下一拍不引入额外空拍。skid 深度和流水级数按参数扫描，不固定为一个串行分叉 FSM（HUB_IDN §3.2、§5、§9.1）。
- L2 bank busy、LDP/NWB FIFO 满和链路插级只产生停顿计数，不产生协议致命错误；最终写入握手只能在数据真正落 bank 后产生。
- 验证发令方按 `src` 计数：H2C/HUB_IDN 多播应写量 = 存储字数 × 目的核数；C2H 由本核 CCU 计本链路握手。

## 3 MAE_CRU 数据与跨模块阶段

- **报告触发**：各核先 C2H 写 L2，CCU 写入握手计满后才发报告。MAE_ENG 按地址配对并收齐参与核报告后启动合并；覆盖报告合法到达次序变化、延迟和不同对象地址，检查 CRU 不承担报告收集/等待（MAE_CRU §4.2）。
- **四象限读**：NI 读口按同址读出 4 × 32 B；参与掩码外不等待，参与象限 busy 或跨拍返回时只在所需份对齐后合并，结果不依赖返回先后；掩码外放随机数据且施加 busy，确认不影响结果与放行（MAE_CRU §4.1）。
- **运算参考模型**：逐元素相加覆盖 FP16、BF16、MXFP6 g32、FP8 输入以及 BF16、FP16、MXFP6 稠密/按列表压缩输出；标量按 FP32 合并，读集按位取并。加法次序按象限固定，按正文数值语义与已冻结参考模型对拍（MAE_CRU §3、§5.4–§5.5）。
- **残差两指令**：第一条归约写 BF16 L2，LIC 收其完成后才下发第二条残差加；覆盖两路源分拍返回、稠密/紧凑残差输入的解码及缺位补 0、稠密残差输出及 Fusion 按块循环。紧凑输入的长度由引擎按 token 长度表读取；结果要送核时另发 H2C 指令（MAE_CRU §3.1a、§3.4–§3.5；MAE_ENG §9.4）。
- **写回与完成**：NI-L2C ready 随机拉低，检查保持当前拍；区分 CRU 全部结果交出、引擎计满目的 L2 写入握手及 MAE 通知 LIC。压缩输出长度表由引擎写完再完成；不以 CRU 内部输出时刻代替目的完成（MAE_CRU §2.1、§5.3、§5.6；MAE_ENG §10）。
- **吞吐与单位边界**：无 bank 冲突且 ready 连续有效时，合并流水支持正文规定的每拍结果速率，压缩后不足一字时按输入侧每拍一字计；NI-L2C 等合并点只在单位边界切换来源，单位内不交错（MAE_CRU §6.2；传输协议 §3.9）。

## 4 变长对象与跨模块依赖

- 生产方将 token 按实际长度紧挨写入，长度表独立写入；验证 24 bit 表项（16 bit 字节数 + 8 bit `tokmax`）地址、字节数和跨字对齐。
- MAE 先搬长度表再搬对象，同一链路上表必须先于数据落地；读表项之和决定数据量。长度转发在搬完后以实际发出项数通知应写量，可晚于数据到达；CCU 收到应写量且写计数满足后才消费。覆盖跨字长度、满窗口和正文规定的超窗口检查（传输协议 §4.3、§8.6）。
- 验证压缩输出的 keep 位图/序号列表由 MAE_ENG 读入并交给 CRU，CRU 不读取或回填长度表；L1/L2 完成跨字节对齐和 bank 落位，HUB/MAE 不做字节移位。

## 5 错误、复位和性能

- 硬件错误用例限定在正文已有的协议/引擎检查范围，并核对发现与上报责任方；不要求 HUB、HUB_IDN 或 CRU 新增检查、ERROR 状态或错误端口。编码/列表一致性和非法输入可用仿真断言检查，不据此规定硬件响应（MAE_CRU §7；HUB_NOC §10；HUB_IDN §8；MAE_ENG §13.1；传输协议 §9）。
- ready 低、bank busy、长度转发晚到为正常流量事件；复位覆盖各模块主文档指定的在途状态清除，不产生虚假握手或完成通知（MAE_CRU §7；MAE_ENG §13.2、§13.4）。
- 统计每条 H2C、HUB_IDN、C2H 和 NI-L2C 的 ready 低拍、bank busy、分支等待、写入握手和实际吞吐；记录 simulator、seed、参数集、参考模型版本和结果。

## 6 退出条件

每项测试记录所覆盖的现行条款、参数、seed、工具/参考模型版本及结果。未完成的接口核对、周期验证和数值标定回填当前未决项台账；“掩码外不等待”等正文已定行为仍需验证，但不得重新列为待架构裁定。HUB 级数/分叉/回程、IDN 32 B 吞吐、CRU 对齐/编码/压缩、归约→残差依赖和紧挨对象长度协议均需有对应结果。
