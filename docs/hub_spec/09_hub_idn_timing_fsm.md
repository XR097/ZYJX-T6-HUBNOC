# HUB_IDN 时序与分叉状态机

## 1 输入握手

`IDLE` 中，当 MAE IDN 出口 `valid` 且输入 ready 为 1 时锁存一拍完整记录：32 B 数据、地址字段、`src` 和 `core_set`。ready 为 0 时保持所有字段不变；不拆拍、不攒字、不等待四核同拍成交。

## 2 分叉状态

锁存后进入 `FANOUT`。对 `core_set` 中每个尚未取走的核拉高其 `en`，各核独立观察 ready：

1. 某核 ready 成交时清除该核的 pending 位；
2. pending 位非空时继续保持该核的字段和 `en`；
3. 所有 pending 位清零后进入 `ACCEPT_NEXT`，清除旁带并允许上游下一拍。

`core_set` 外的核永远不产生 `en`。分叉点可拆成多级通用链路块；每级 skid 只保存本级一拍和 pending 位，不建立整流或独立多播缓存。

## 3 写入握手回程

四条输出链路可在不同周期返回 `valid+src`。`idn_ack_merge` 只做透明汇总并按 `src` 交 MAE_ENG；回程没有 ready，不能反过来改变已发出的数据。引擎按核集合大小计应写量并决定指令完成。

## 4 复位与停顿

复位清除输入寄存器、所有 pending 位、skid 和在途回程，不保留跨指令状态。某核 NWB 暂停时先消耗该核分支的 skid；分支耗尽才拉低上游 ready，导致整个输入流按最慢目的核停顿。单播时该停顿只影响唯一目的核。

## 5 验收场景

覆盖单播、双核轮排、四核均分、随机多播、各目的 ready 独立抖动、随机流水级数和写入握手回程延迟。检查每个字只出现在 `core_set` 指定核、字段逐位保序、写入握手数量等于实际目的核数，并验证 M0 输入上限始终为 32 B/拍。
