# HUB_IDN 流水与分叉时序

> 描述可流水重叠的占用与已取位规则，不规定串行 IDLE/FANOUT/ACCEPT_NEXT 状态机。依据 HUB_IDN §3、§5、§8–§9 与传输协议 §3.3。

## 1 输入及旁带

MAE IDN 出口以 `en && ready` 交付一拍：32 B `din`、全 1 的 `be`、`addr/seg/src` 与 4-bit 核集合。`en` 不依赖 ready；停顿时保持尚未成交的记录。核集合可按每个存储字改变，随字到最后分叉点；到核链路不携带核集合。

## 2 分叉占用与接替

当前拍对核集合内、尚未取走的目的拉高 `en`，只由集合/已取位决定，不看目的 ready。某目的 `en && ready` 后记为已取，其余未取目的继续保持本拍数据及旁带；已取目的不重复发送。

全部目的取走后才释放当前拍。满吞吐实现允许最后未取目的成交与上游下一拍在同一拍接替，更新新拍核集合和已取位；所有目的连续可接收时，每拍可收一个 32 B 输入字，不增加清旁带或 ACCEPT_NEXT 空拍。

分叉可拆成多级通用链路块；各核分支 skid 与 NWB 入口 FIFO 吸收快慢差。慢核分支还有余量时，快核照常接收；余量耗尽后才反压上游。分叉点不新增整流或专用多播存储，skid 深度与级数由设计者/后端确定。

## 3 写入握手回程

各核 NWB 真正写进 L1 bank 后返回 `valid+src`，可异拍到达、同拍也可有不同 `src`。HUB_IDN 原样转交或按 `src` 归并，不能丢失、重复或串源。回程没有 ready，与正向独立插级；引擎按指令实际写入量计数，HUB_IDN 不判断完成、不等回程才发下一字（HUB_IDN §2.1、§7）。

## 4 复位与验证

复位清在途拍和已取位，无跨调用状态；不新增运行时检查或 ERROR 状态（HUB_IDN §8）。

覆盖单播、双核轮排、四核均分、随机多播、各目的 ready 独立抖动、级数/分叉变化及回程延迟。除逐字保序、核集合与旁带对齐、握手归属外，必须验证连续可接收时 back-to-back 每拍一字，以及慢分支容量耗尽后的停顿恢复。空集合等未规定输入仅用于验证约束核对，不自行规定硬件错误响应。
