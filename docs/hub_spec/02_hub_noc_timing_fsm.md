# HUB_NOC 时序与实现分解

## H2C 单源流水

1. MAE_ENG 给道 n 的 L2 读 `en/addr`；L2 busy 时保持请求重发，HUB 不累加地址。
2. L2 返回的 `dout/vld` 连同目的 `addr/seg/be/src` 和核掩码进入通用链路块。H2C 掩码是单位的指令参数，在单位内一致，并随每拍流水到分叉点（MAE_ENG §3.2、§7.1）。
3. 分叉点对掩码内尚未取走的目的拉高 `en`，`en` 不依赖 ready；目的以 `en && ready` 取走。全部目的取走后可收下一拍，满吞吐实现必须允许当前拍最后目的成交与下一拍接替，不强制插空拍。
4. 每段可插寄存器/skid；分叉位置、级数和回程级数由后端参数决定（HUB_NOC §3.5、§5.2）。

H2C 只有 L2 一个源；CRU 结果先写 L2，后续另发 H2C 搬运。HUB 不做源选择，但同一道上的单位仍须保序、不交错（HUB_NOC §5.3、§9）。

## C2H 直通

核 n 的集成输出端口经 C2H 直通 L2WP 第 n 条。下游 ready 作用于发送 FIFO 的发送；FIFO 将满产生 `stall_tx` 门控 CCU，恢复后继续（传输协议 §7.1）。HUB 不增加专用存储、扇入或仲裁；沿途通用链路块仍可含寄存器/skid（HUB_NOC §3.5、§4、§6）。

## 写入握手

- LDP 最终写进 L1 bank 后回 `valid+src`；H2C 每道最多四项/拍，同拍可有不同 `src`，可归并计数或原样转交，不丢、不重、不归错源。
- L2 象限 n 经 C2H 回核 n 的 CCU：每拍至多一个不带号的 `valid` 脉冲，不携带 `src`。
- 两类回程都没有 ready，回程级数与正向独立；不得等回程到达才发下一拍（HUB_NOC §7）。

## 命令网

64-bit `en/ready/data` 消息透明转发，消息首字含长度。同链路保序，数据与命令两网不保证到达先后。标量经 C2H→L2→MAE_CRU；命令网只转发正文列出的指令、事件、完成、长度转发、发出报告和错误消息（HUB_NOC §8）。

## 参数

各段级数、skid 深度、分叉位置、回程级数以及道首级停发 L2 读的将满阈值（深度 − 在途读拍数）为 RTL 参数/后端约束。L2 busy 是读端冲突反馈，不是 HUB 另设的门限。验收随机化级数、分叉、ready 与回程时延（HUB_NOC §3.5 A1–A7）。
