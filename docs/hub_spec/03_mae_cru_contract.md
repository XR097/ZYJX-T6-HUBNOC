# MAE_CRU 当前合同

> 依据：2026-11-08 正文 `MAE_CRU.md`、`MAE_ENG.md` 与 `DATA_TRANSFER_PROTOCOL.md`。本文件整理现行责任边界，不新增硬件接口或检查。

## 1 位置与数据路径

`MAE_CRU` 是 MAE 组的搬运运算级，与直通、`MAE_DSU` 并列；合并种类、参与象限、加数编码、输出编码和源/目的地址由搬运指令指定，`MAE_ENG` 交给本单元解码后的参数与控制（MAE_CRU §1.1–§1.2）。

核间合并的数据路径为：各核 C2H → L2 本核象限 → NI 读口 → MAE_CRU → NI-L2C 写客户 → L2。参与核把同一输出位置写在各自象限的同一象限内地址；结果若要送核 L1，另由一条 L2→L1 搬运指令经 H2C 下发（MAE_CRU §2.3、§4；MAE_ENG §4.2）。

`MAE_CRU` 只与 `MAE_ENG`、`NI_INT` 相连，不直接接 C2H、H2C 或 HUB_IDN，不设用于收集各核产出的入口 FIFO、合并存储或按地址到达份数表（MAE_CRU §1.1–§1.2）。

## 2 报告、读入与对齐

- 各核 CCU 数满 C2H 返回的 L2 写入握手后发送“发出报告”；MAE 按报告目的起始地址配给合并指令，收齐参与核报告后才执行。CRU 自身不计报告、不等待核的产出到达（MAE_CRU §4.2）。
- NI 读口为 4 × 32 B，归约时读四象限同址。某象限 busy 可使该份晚到；CRU 等当前地址的参与份到齐后再合并，掩码外象限不等待。对齐方式由设计者确定，必须不丢、不错拍（MAE_CRU §4.1）。
- 残差加的两路对象由引擎按各自地址分拍读入，CRU 对齐同一 token 的同一通道段后相加（MAE_CRU §3.1a）。

## 3 运算与编码

| 形态 | 现行要求 |
|---|---|
| 逐元素相加 | 部分和归约或残差加；输入编码为 FP16、BF16、MXFP6 g32、FP8，逐路由指令给出；输出为 BF16、FP16、MXFP6 稠密或按列表压缩 |
| 标量合并 | FP32 标量求和、取最大或 `(最大值, 缩放和)` 对合并；输出 FP32 |
| 读集合并 | 参与份按位取并；输出并集位图 |

加法次序按象限号固定，结果不随各核写入先后或象限 busy 先后改变。内部宽格式、并行 lane 数和超四份累加能力由设计者确定；外部数值合同按 FP32 固定象限次序相加、输出 BF16/FP16 末次 RNE、输出 MXFP6 按 QNT 规则量化一次的参照逐位一致，不由实现重新选择（MAE_CRU §3、§5.4–§5.5、§6.2）。

各路输入通常定长，唯一例外是残差加的残差输入可为 MXFP6 紧凑记录：长度由引擎按 token 长度表读取，CRU 按段头 keep 展开、缺位补 0，再与另一加数相加；CRU 不自行解析长度表（MAE_CRU §3.4–§3.5）。

核间 K 切分残差位点先由一条指令归约并以 BF16 写 L2，再由一条指令读归约结果与残差流、做残差加。LIC 在第一条执行完后下发第二条；分块流式时由 Fusion-L3PU 段按块循环。残差加输出为稠密格式；按列表压缩只适用于指令已有 keep 列表的合并（MAE_CRU §3.1a）。

## 4 地址、压缩与完成

两侧每拍地址由搬运引擎给出。压缩所需 keep 位图或序号列表由引擎读入在用列表缓存后交给 CRU；CRU 随结果交回每条记录的实际字节数和 tokmax，引擎据此推进地址并写独立 token 长度表（MAE_CRU §2.1、§5.6；MAE_ENG §9.4）。

CRU 的“合并完成”表示本条指令全部结果已交出；目的写入完成由引擎计 L2 bank 返回的带 `src` 写入握手判断。压缩输出还需按正文完成长度表写入，再由 MAE 带指令标号通知 LIC（MAE_CRU §2.1、§5.3、§5.6；MAE_ENG §10.2–§10.3）。

两侧每段使用 ready 握手；任一段停顿时执行引擎统一停发。正常无 bank 冲突时，解码、合并和编码需跟上每拍四份读入、每拍一个 32 B 结果写出的速率；压缩后不足一字时按输入侧每拍一字计，不规定固定时延（MAE_CRU §6.1–§6.2）。

## 5 检查与复位边界

CRU 不做运行时检查，不增设硬件错误状态或错误响应；debug 检查按正文留待统一确定。复位清在途读入与合并，无跨调用合并存储（MAE_CRU §7）。现有协议和引擎的致命检查沿用 `DATA_TRANSFER_PROTOCOL.md` §9、`MAE_ENG.md` §13.1 的责任边界；输入编码、列表与记录的一致性可在验证中断言，不据此扩展 CRU 硬件合同。
