# 00 公共约定：协议 B 字段、信用、格式与全局参数

版本：初版 v0.1（2026-10-28），供负责人审阅。

本文件是 hub 各子单元 spec（01–06）共用的底层约定。凡 01–06 中出现的字段名、位宽、编码、参数名，都以本文件为准；本文件又以四份 PDF 为准：协议权威是 `SPEC_TRANSFER_PROTOCOL_V1.5.pdf`（下称"协议篇"），模块合同是 `HUB_NOC.pdf`、`HUB_RHUB.pdf`，存储格式见 `DATA_LAYOUT_V1.5.pdf`（下称"数据组织篇"）。页码按 PDF 页脚。

## 0. 标注约定

PDF 里很多数值写的是"建议值"，还有一些细节 PDF 没写、但写 RTL 前必须有个定法。为了让审阅人一眼分清哪些是 PDF 已定、哪些是我们补的，全套 spec 统一用下面四种标注：

| 标注 | 含义 | 审阅时要做什么 |
|---|---|---|
| （无标注，带 PDF 出处） | PDF 正文已定 | 核对引用即可 |
| 【建议值·OI-xx】 | PDF 给的是建议值，本 spec 先按它冻结；对应 `open_issues_spec_stage.md` 的 OI 编号 | 随 OI 关闭确认，改值不改结构 |
| 【拟定】 | PDF 没写，本 spec 为写出微架构而补的做法；不改变 PDF 的带宽、VC 语义、侧带位宽和归属边界 | 负责人或对口模块作者确认 |
| 【参数】 | 取值待仿真或标定，RTL 中做成 parameter | 不阻塞 spec，仿真后回填 |

所有【拟定】项在 README 的"spec 新增待确认项"里汇总一遍，便于一次性过审。

## 1. 术语

| 术语 | 含义 |
|---|---|
| 拍 | hub 中心时钟的一个周期；全套 spec 的时延都以拍计 |
| flit | 一拍传输的 32 B 容器，含 4 个 8 B 字（协议篇 p13 §4.2.1） |
| 道（lane） | D-40 下行的一条 32 B/拍通道，共 4 道；道 q 硬连 L2 象限 q（HUB_NOC p7 §4.1.3） |
| 单位 | 一次传输的逻辑单位，末拍带 `last`；单位末尾补到 8 B 字（协议篇 p14 §4.2.3） |
| fire（成交） | 本拍完成一次传输。协议 B 上 `vld = 1` 即成交（信用已在发端预扣）；hub 内部握手 `vld && rdy` 即成交 |
| 位点 | 一层里的一次矩阵乘；位点边界由 barrier 和 GO 同步（HUB_NOC p2 §1.4） |
| 格式感知端点 | 需要解析 SFD 的节点：HUB-DN 段片切分、HUB-ATT、R-hub（协议篇 p12 §4.1.8）。HUB-UP、单写口、D-40 与上行链路只搬字 |
| WCNT / RCNT | L2 侧的写完成 / 读完成计数器，hub 只读不持有（HUB_NOC p14 §4.5.2–4.5.3） |
| SD | hub 位点描述符（hub site descriptor），由 LIC 下发、GO 后生效（HUB_NOC p6 §3.2） |

## 3. 链路层（协议 B）

### 3.1 每拍字段

协议 B 每拍带且只带三个链路层字段（协议篇 p13 §4.2.2）：

| 字段 | 位宽 | 含义 |
|---|---|---|
| `vld` | 1（一发多收时为按目的的位向量） | 发送方本拍数据有效 |
| `last` | 1 | 本传输单位的末拍 |
| `nw8` | 2 | 本拍有效 8 B 字数，编码 `2'b00` = 1 字 … `2'b11` = 4 字；非末拍恒为 `2'b11` |

不设逐字节有效位。接收方按"本拍成交 + `nw8`"在本地生成写使能，粒度是接收方自己的 bank 字：AB 8 B、WB 136 bit、L2 32 B 行（协议篇 p14 §4.2.4）。对 hub 而言，这条规则落在单写口：L2 一行 32 B 整行写，`nw8 < 4` 的末拍其余字按补零写入（单位末尾补到 8 B 字、补齐字节写 0，协议篇 p14 §4.2.3）。

D-40 下行中，`vld` 与 12 bit 侧带头里的目的掩码共同表示"发给哪些核"：本 spec 规定每道物理上只出一根 `vld`，目的掩码 `dest_mask[3:0]` 即按目的的位向量【拟定】。这样 12 bit 侧带头的位宽不变，核侧以 `vld && dest_mask[c]` 判断本核是否收本拍。

### 3.2 单位边界

每个传输单位末尾补到 8 B 字，补齐字节写 0；下一单位从下一拍的字 0 开始。例外是段片流：整条重放流是一个单位，段片按字节背靠背排列，使每道实收不低于 31 B/拍（协议篇 p14 §4.2.3；HUB_NOC p8 §4.1.7）。

### 3.3 成交规则

协议 B 是信用流控，没有 `rdy`：

1. 发端为每个信用单位持一个计数器，计数 ≥ 1 才发，发则减 1；返还脉冲到手的下一拍加回（协议篇 p19 §4.4.6 及 p18 图 (d)）。
2. `vld = 1` 的一拍即成交，接收方必须收下（信用保证不溢出）。
3. 多播：目的掩码含 n 个核时，n 个计数全部 ≥ 1 才发，各减 1（协议篇 p20 §4.4.8）。
4. 同一单位内 `data`、侧带头在未发出前保持；发出与否只由信用决定，不受接收方组合逻辑影响，没有输入到输出的组合通路（与协议篇 p14–15 §4.3.3 协议 A 的成交规则同一原则）。

hub 内部子单元之间用 `vld/rdy` 握手：`fire = vld && rdy`；`vld` 不得依赖 `rdy`；`vld` 拉起后 `data` 与附带字段保持到 `fire`【拟定，沿用协议 A 规则】。

### 3.4 信用返还线

接收方每弹出一个 flit，在下一拍对应返还线上打一个单拍脉冲；返还线与数据线同级寄存，到达发送方的下一拍才可用。不用带内返还（协议篇 p19 §4.4.6）。

| 方向 | 每核根数 | 组成 | 信号名（本 spec） |
|---|---|---|---|
| D-40 下行（核 → hub） | 10 | VC0 × 4 道、VC1 × 4 道、VC2 × 1、VC3 × 1 | `dn_crd_vc0[c][3:0]`、`dn_crd_vc1[c][3:0]`、`dn_crd_vc2[c]`、`dn_crd_vc3[c]` |
| 上行（hub → 核） | 4 | 每 VC 1 根；VC2 的信用 = R-hub 入口 FIFO 空位 | `up_crd[c][3:0]` |

四核合计 4 × (10 + 4) = 56 根（HUB_NOC p3 §2；协议篇 p19 §4.4.6）。

## 4. 侧带头

位宽（12 / 14 bit）与字段内容是协议权威给定的，不得改；字段次序与编码是协议篇 p18 图 FIG-V15-PROTOCOL-FLIT 的建议值，本 spec 按它冻结【建议值·OI-01】。不用的字段填 0。

### 4.1 下行 12 bit（`dn_sb_t`）

| 位 | 字段 | 位宽 | 说明 |
|---|---|---|---|
| [11:8] | `dest_mask` | 4 | 每核 1 bit，bit 8 = 核 0 … bit 11 = 核 3；`4'b1111` 为四核多播 |
| [7:6] | `vc` | 2 | 0 重放、1 数据、2 响应、3 控制 |
| [5:3] | `cls` | 3 | 类别，按 VC 解释，见 4.3 |
| [2] | `last` | 1 | 末拍 |
| [1:0] | `nw8` | 2 | 有效字数 |

核对例子（协议篇 p18 图 (a)）：VC1、类别 3（PS 读回）、只发核 2、末拍、3 个字 → `0100 | 01 | 011 | 1 | 10` = `12'h45E`。

### 4.2 上行 14 bit（`up_sb_t`）

| 位 | 字段 | 位宽 | 说明 |
|---|---|---|---|
| [13:12] | `vc` | 2 | 0 窄口、1 数据、2 部分和、3 控制 |
| [11:9] | `cls` | 3 | 类别，见 4.3 |
| [8] | `last` | 1 | 末拍 |
| [7:6] | `nw8` | 2 | 有效字数 |
| [5:4] | `owner` | 2 | 归约属主核号，仅 VC2 用，由 CCU_CTL 给出 |
| [3:0] | `region` | 4 | 仅 VC1 用：类别 0 时为 HUB-UP 游标表索引，类别 1 时为环号 |

源核号与道号由物理链路隐含，不占字段（协议篇 p19 §4.4.2）。

核对例子（协议篇 p18 图 (b)）：

- VC1、类别 1（环写）、环号 5、非末拍、4 字 → `01 | 001 | 0 | 11 | 00 | 0101` = `14'h12C5`。
- VC2、类别 0（部分和）、属主核 1、末拍、2 字 → `10 | 000 | 1 | 01 | 01 | 0000` = `14'h2150`。

这三个例子作为 `hub_pkg` 打包 / 解包函数的单元测试向量（见 07）。

### 4.3 类别字段

下行（HUB_NOC p8 §4.1.6；协议篇 p18 图 (c)）：

| VC | 类别 0 | 类别 1 | 类别 2 | 类别 3 | 类别 4 | 5–7 |

## 5. 载荷格式描述 SFD（`sfd_t`）

每条流在位点开始前绑定一份 SFD，位点内不变；hub 侧的 SFD 放在 hub 位点描述符里（协议篇 p11 §4.1.1）。字段与位宽按协议篇 p11 §4.1.2 建议值冻结【建议值·OI-01】，合计 39 bit：

| 位 | 字段 | 位宽 | 编码 |
|---|---|---|---|
| [3:0] | `fmt` | 4 | 0 不透明字节、1 紧凑激活记录、2 稠密 MX 组流、3 MXINT 数字平面 + 尺度平面、4 WB 136 bit 字流、5 KV 存储页、6 P′ 记录、7 Q 记录、8 BF16 向量、9 FP32 标量组、10 位图、11 索引或索引加值列表、12 R-hub 组、13 控制消息；14、15 保留 |
| [6:4] | `w` | 3 | 0 = 2 bit、1 = 4、2 = 6、3 = 8、4 = 16、5 = 32；6、7 保留【拟定：PDF 只给取值集合】 |
| [8:7] | `grp` | 2 | 0 = 32、1 = 64、2 = 128、3 = 无组【拟定编码】 |
| [10:9] | `scale` | 2 | 0 组内联、1 段头、2 独立平面或前置、3 无尺度【拟定编码】 |
| [12:11] | `planes` | 2 | 平面数 − 1（1–4） |
| [14:13] | `len_src` | 2 | 0 命令计数、1 记录头与段头自定界、2 列表计数、3 末拍标记【拟定编码】 |
| [38:15] | `count` | 24 | 元素数、组数或字数，按 `len_src` 解释 |

hub 内只有三处读 SFD（协议篇 p12 §4.1.8）：

| 读者 | 用哪些字段 | 用途 |
|---|---|---|
| HUB-DN 段片切分 | `fmt`（须为 1）、`w`（6 或 8） | 按 w 现算段长、切段片 |
| HUB-ATT | `fmt`（10 位图 / 11 列表） | 校验输入、选择 OR 或透传 |
| R-hub | `fmt`（入口 8、出口 12）、`grp`（32）、`scale`（组内联） | 校验位点配置；结构本身固定 |

hub 侧涉及的流，其 SFD 取值见协议篇 p12–13 §4.1.9，摘录如下：

| 流 | fmt / w / grp / scale | 单位与长度 |
|---|---|---|
| 激活重放（D-40 VC0 类别 0） | 1 / 6 或 8 / 32 / 段头 | 整条段片流一个单位，段头自定界 |
| 激活灌入（D-40 VC0 类别 1） | 1 / 6 或 8 / 32 / 段头 | 整记录，记录头给长度 |
| BF16 部分和（上行 VC2） | 8 / 16 / 无 / 无 | 32 B 条目，命令计数 |
| R-hub 回送（D-40 VC2 类别 0） | 12 / 6 / 32 / 组内联 | 1 flit = 25 B + 2 B 组序号 |
| 标量（上行 VC0 类别 4、下行 VC2 类别 1） | 9 / 32 / 无 / 无 | 1 flit |
| 位图（上行 VC0 类别 0–2） | 10 / 1 / 无 / 无 | 64–512 bit 一条 |
| 列表记录 | 11 / 24 等 / 无 / 无 | 记录头给"计数 − 1" |
| 事件与控制（VC3） | 13 | 单 flit，首字节为消息类型 |

位图的元素位宽 1 bit 不在 `w` 的 6 个取值里。本 spec 规定 `fmt = 10` 时忽略 `w`【拟定】。

子字节位序：低位在前，码 i 占值区第 [w·i, w·i + w) 位，字节 b 存第 [8b, 8b + 8) 位。核对例子：5 个 E2M3 码打包成 `1C 4B 21 38`（协议篇 p12 §4.1.3）【建议值·OI-01】。hub 内只有 R-hub 出口量化器要按这个位序打包；HUB-DN 按字节切段片，不拆码。

## 6. VC3 消息

### 6.1 背景

位点完成、WB 槽释放、份释放、属主核完成、系数就绪、gather 计数、GO 七种事件都是 VC3 上的单 flit 消息（属主核完成至多 3 flit），载荷首字节为消息类型、其余为字段，不拉专线（协议篇 p22 §4.4.12；HUB_NOC p15 §4.5.8）。此外 VC3 还承载核描述符转发、判决广播、区块并集广播、档表同步与表装载（HUB_NOC p6 §3.2、p10–11 §4.2.8–4.2.9、p13 §4.4.5、p14 §4.4.10）。这些是多 flit 单位，以 `last` 定界。

四份 PDF 都没有给类型码表（OI-23）。hub 的上行 VC3 分流必须按首字节查表，所以本 spec 先拟一张表供 RTL 骨架使用，编码待协议篇或 CCU_CTL 篇给出后整体替换【拟定·OI-23】。

### 6.2 类型码表（暂定）

| 码 | 消息 | 方向 | hub 内处理者 | 字段（字节偏移：内容） | flit 数 |
|---|---|---|---|---|---|
| `8'h01` | 位点完成 | 核 → hub | HUB-UP → HUB-SYNC | 2–3：point_id；4–5：nflit；6–9：本核本位点段片解析器等重放的拍数（供 hub 按位点汇总，HUB_NOC p9 §4.2.2） | 1 |
| `8'h02` | WB 槽释放 | 核 → hub → MAE | HUB-UP 透传至 MAE 事件口 | 1–31：透传 | 1 |
| `8'h03` | 份释放 | 训练核 → hub → NI SDN | HUB-UP 透传至 SDN 事件口 | 1–31：透传 | 1 |
| `8'h04` | 属主核完成 | 核 → hub → LIC | HUB-UP 透传至 LIC | 透传 | ≤ 3 |
| `8'h05` | 系数就绪 | OPT 核 → hub → LIC | HUB-UP 透传至 LIC | 透传 | 1 |
| `8'h06` | gather 计数 | MAE → hub → 核 | HUB-DN 注入 | 透传 | 1 |
| `8'h07` | GO | hub → 核 | HUB-SYNC 生成 | 2–3：point_id | 1 |
| `8'h08` | 档表同步 | 核 → hub → 参与核 | HUB-UP → HUB-DN 多播 | 透传 | 单位 |
| `8'h10` | 核描述符 | LIC → 核 | HUB-DN 转发 | 透传 | 单位 |
| `8'h11` | MAE 事件（模板完成计数等） | MAE → 核 | HUB-DN 注入 | 透传 | 1 |
| `8'h12` | K 切分判决广播 | hub → 核 | HUB-ATT 生成 | 见 04 | 单位 |
| `8'h13` | 区块并集广播 | hub → 核 | HUB-ATT 生成 | 见 04 | 单位 |
| `8'h20`–`8'h27` | 表装载：阈值套、节点档表、祖先掩码块、父槽表、TAG 表、随机数、Batch 行表 | hub → 核 | HUB-DN 读 L2 固定区发出 | 透传 | 单位 |

hub 只解释首字节，以及位点完成、GO 两种消息的字段；其余消息透传。属主核完成去 LIC 是本 spec 的推断：PDF 没写它的接收方【拟定·OI-23】。

## 7. 记录头（hub 只透传，部分字段由 HUB-ATT 填）

| 记录 | 结构 | 来源 |
|---|---|---|
| 紧凑激活记录头 | 8 B：tokmax 1、非零数 2、记录长度 2、标志 1、token 序号 2；每段 = 段头 5 B（E8M0 1 + keep 位图 4）+ F 标志 ⌈ks/8⌉ B + 值区 ⌈w·ks/8⌉ B；记录末补到 8 B 字 | 数据组织篇 p10 §3.1 |
| 列表环记录头 | 8 B：模板号 4 bit、序号 16、格式位 1（0 位图 / 1 每项 3 B 行号）、计数 16（条数 − 1），共 37 bit 补到 8 B；有效条数 ≤ 65,535 | 数据组织篇 p20 §6 |

HUB-DN 段片切分要读两处：记录头的"记录长度"（定界整条记录），以及每段段头 keep 位图的置位数 ks（按 5 + ⌈ks/8⌉ + ⌈w·ks/8⌉ 现算段长）。见 02。字段在字内的位序与字节序随 ISA 定（数据组织篇 p20），本 spec 按低字节在前、字段按上表次序排列【建议值·OI-01】。

## 8. 错误与计数的分级

### 8.1 致命断言（6 类）

协议不重传，违例只能靠检查发现。下面 6 类断言每类一个比较器，触发即报致命类错误事件，由 LIC 收束（HUB_NOC p8 §4.1.7；协议篇 p22 §4.4.13）。hub 侧落在哪个子单元：

| 码 | 断言 | hub 内检查点 | 说明 |
|---|---|---|---|
| `ERR_CRD_RANGE` (1) | 信用计数下溢或超过初值 | HUB-DN 信用计数器（下行）；HUB-UP 入口队列占用（上行） | 上行由 hub 作接收方，等价检查是"入口 FIFO 占用 > 深度" |
| `ERR_LAND_OVF` (2) | 落地 FIFO 写入时已满 | HUB-UP 入口 FIFO、R-hub 入口 FIFO | 下行落地 FIFO 在核侧，由核侧检查 |
| `ERR_MC_UNPAIRED` (3) | 末拍 flit 的多播返还不配对 | HUB-DN 多播跟踪 | 返还来自未在掩码内的核，或未返还目的数下溢 |
| `ERR_SHARED_2FLIT` (4) | 共享池 VC 同核同拍收到 2 flit | HUB-DN 发送端自检（4 道合并后同核 VC2 或 VC3 计数 > 1） | 接收方检查在核侧；hub 侧再查一次，便于定位 |
| `ERR_POINT_ID` (5) | 位点号不匹配的位点完成 | HUB-SYNC | |
| `ERR_BARRIER_TO` (6) | barrier 超过看门狗 | HUB-SYNC | |

错误事件格式（经 hub 控制口送 LIC）：`err_vld`、`err_code[3:0]`、`err_core[1:0]`、`err_vc[1:0]`、`err_lane[1:0]`、`err_info[15:0]`（如位点号）【拟定】。同拍多个错误按码值小者先报，其余置"错误溢出"粘滞位，不丢失计数。

### 8.2 流量性停顿（计数，不报错）

信用为 0、SDN 停发、R-hub 入口满、w = 8 超口降速只按位点计数，不报错（HUB_NOC p8 §4.1.7）。hub 侧计数器统一 32 bit，按位点锁存，在 GO 时把上一位点的值送 LIC 汇总到 CIF；调用级计数窗与看门狗在 LIC（HUB_NOC p5 §3.1）。各子单元的计数器清单在 02–06 各自的"计数器"一节。

非致命异常计数（列表环满、非法类别等）与停顿计数走同一锁存通路。

## 9. RTL 编码约定

按仓库 AGENTS.md：

- SystemVerilog，四空格缩进，显式位宽，一行一个声明。
- 单时钟 `clk`、同步复位 `rst_n`（低有效）。复位后所有信用计数器装入初值参数，所有 FIFO 清空，所有 `vld` 为 0。描述符寄存器复位为"全部禁用"（目的掩码 0、R-hub 使能 0）。
- 模块与文件名 snake_case：`hub_top.sv`、`hub_dn.sv`、`hub_up.sv`、`hub_att.sv`、`hub_sync.sv`、`rhub.sv`；类型与参数放 `hub_pkg.sv`。
- 保留 V1.5 字段名：`vld`、`last`、`nw8`、`vc`，以及信用信号名中的 `crd`。
- 子单元之间的握手统一 `*_vld` / `*_rdy` / `*_data` 命名，`fire` 在模块内部局部定义。
- 未冻结的位宽和深度一律做 parameter，默认值取本文件 §2。
