# R-hub 接口合同

本文件把 `docs/HUB_RHUB.pdf` 的需求整理成可用于 RTL 和模块级验证的接口合同。原始规格中的建议值、待审查项和待标定项保持为参数；本文件不替代原始 PDF。

## 1. 边界和职责

R-hub 是挂在 HUB 中心的 K 维部分和归约单元，当前服务 Qwen Prefill 的 gate/up K 切分（HUB_RHUB §1.1、§1.5，PDF 第 1～2 页）。它接收四个计算核的 BF16 部分和，按固定顺序归约，按 32 元素组量化成 MXFP6 g32，再交给 HUB-DN 的下行 VC2 回送归约属主核。

R-hub 不访问 DDR/L2，不做地址匹配、L2 读改写、跨拍累加、残差加、判决或 D-40 道选择。上行分流、信用返还和下行选道归 HUB-UP/HUB-DN；部分和按 pid 排序由核侧 E6/F1b 出口队列保证（HUB_RHUB §1.3、§2.2、§6，PDF 第 2、6～7 页）。

## 2. RTL 子模块和资源所有权

| 子模块 | 主要职责 | 资源/状态所有权 |
|---|---|---|
| `rhub_ingress_fifo[4]` | 每核接收一个上行 VC2 flit，提供满/空和 `rhub_pop` 事件 | 每核 FIFO、读写指针、满计数 |
| `rhub_head_align` | 检查参与核头部是否齐备，形成一次对齐消费 | 参与核掩码、对齐握手、pid 假设 |
| `rhub_bf16_tree` | 16 lane、两级固定顺序 BF16 RNE 加法 | 加法流水寄存器，无跨拍累加状态 |
| `rhub_group_buffer` | 暂存同一归约流的第一条 16 元素结果 | 32 B 暂存、组相位/组序号 |
| `rhub_mxfp6_quant` | 32 元素 amax、E8M0、E2M3 g32 编码、RNE 和限幅 | 量化流水、异常/饱和标志 |
| `rhub_egress` | 拼装 32 B VC2 flit，携带组序号和归约属主号 | 输出保持寄存器、发送序号、阻塞状态 |

## 3. 外部接口合同

### 3.1 上行 VC2 输入（CC → R-hub）

每个参与核一条协议 B 上行输入；R-hub 通过 HUB-UP 接入，不直接暴露为独立 NoC 链路。

| 字段 | 宽度/语义 | 生产者 | 消费者 |
|---|---|---|---|
| `payload` | 256 bit = 16 × BF16，正好 32 B | 核侧 F1b/E6 出口队列 | 对应 `rhub_ingress_fifo[k]` |
| `vc` | 2 bit，必须为 VC2 | 核侧协议 B | HUB-UP/R-hub 检查 |
| `class` | 协议 B 上行类别；VC2 部分和类别 | 核侧协议 B | HUB-UP 分流、R-hub |
| `last`/`nw8` | 末拍和有效 8 B 字数 | 核侧协议 B | 链路检查；E6 条目固定为 32 B |
| `reduction_owner` | 2 bit，归约属主核；来自上行侧带 | CCU_CTL 产生并由核侧出口队列携带 | `rhub_egress`/HUB-DN |
| `region` | 4 bit 协议字段；R-hub 不用作地址 | 核侧协议 B | HUB-UP 按协议转发 |
| `rhub_pop[k]` | 每弹出一个 FIFO flit 的单拍事件 | R-hub ingress FIFO → HUB-UP | HUB-UP 信用返还 |
| `credit_return[k]` | 由 `rhub_pop[k]` 延迟一拍产生的单拍返还脉冲 | HUB-UP | 核侧 VC2 源队列 |

输入没有 pid、token 或地址标签。正确性前提是所有参与核按同一 pid 序放行；R-hub 只按四路 FIFO 头位置配对，不检测序号错位。四路 owner 不一致属于上游配置/控制合同违约，检查归 HUB-UP/系统验证（HUB_RHUB §2.2、§4.2.1，PDF 第 2、5 页）。

### 3.2 描述符/控制输入

配置由 LIC 生成并随 hub 位点描述符在 GO 后生效：`enable`、参与核掩码、归约属主映射和本流 SFD。R-hub 不维护可编程表；加法顺序和量化规则固定（HUB_RHUB §3.2、§6，PDF 第 3、6～7 页）。

`lane_count`、`fifo_depth` 和流水级数必须作为参数保留，直到 §7 未定项冻结；组序号按归约属主核计数，清零时机待审查，不由描述符任意指定初值。

### 3.3 下行 VC2 输出（R-hub → HUB-DN → CC）

| 字段 | 宽度/语义 | 生产者 | 消费者 |
|---|---|---|---|
| `payload[199:0]` | 200 bit = 25 B：32 × 6 bit + 1 B E8M0 | `rhub_mxfp6_quant` | HUB-DN VC2 |
| `group_seq[15:0]` | 16 bit，放在 32 B flit 的剩余 5 B 中（25 B 量化载荷后） | `rhub_egress` | LAND 在飞表 |
| `dest_mask` | 4 bit，由 `reduction_owner` 形成单播掩码 | HUB-DN | 归约属主核 |
| `vc/class` | VC2、部分和类别 | `rhub_egress`/HUB-DN | 核侧落地口 |
| `last/nw8` | 协议 B 末拍和有效字数 | HUB-DN | 核侧 LAND |

R-hub 不选择具体 D-40 道；HUB-DN 按 VC2 共享池和最短队列选择。输出使用下行 VC2 的类别 0（部分和）编码；VC2 与数据 VC 共用 `wD` 保底槽，R-hub 与 HUB-SYNC 的 VC2 响应由 HUB-DN 仲裁。输出占用一个完整 32 B flit，25 B 量化数据和 2 B 组序号之外的字节按协议约定补齐；`last/nw8` 由 HUB-DN 按所属传输单位生成。L1 集成负责 VC2 落地 FIFO（深度至少 8 是 HUB_NOC 的建议值；R-hub FIFO 深度仍参数化）、类别分路、返还脉冲和 LAND 在飞表；R-hub 只提供结果和发送保持状态。归约属主核的 L1 落地口按类别写入 AB 停放区，LAND 用 `group_seq` 对齐 token/列块（HUB_RHUB §3.1、§4.3.2～4.3.3，PDF 第 3、5 页）。

## 4. 数据不变式

1. 固定加法树：`s01 = RNE_BF16(c0+c1)`，`s23 = RNE_BF16(c2+c3)`，`y = RNE_BF16(s01+s23)`；缺位参与核按 +0 输入，树形不变。
2. 同一归约流中相邻的两条 16 元素结果组成一个 32 元素量化组；第一条结果必须保留 32 B，第二条到齐后才允许量化。R-hub 只依据核侧保证的 FIFO/pid 顺序，不执行 token 匹配。
3. 量化为 MXFP6 E2M3 g32，共享一个 E8M0 尺度；溢出按量化合同 RNE/限幅处理，量化点必须与后处理单元同类量化点逐位一致（参考模型共用同一舍入/限幅定义）。输入流 SFD 使用格式码 8（BF16 向量），输出流 SFD 使用格式码 12（R-hub 组）。
4. R-hub 不跨拍累加，输入到达顺序和链路回压不能改变输出位级结果；量化点必须与后处理单元采用同一逐位规则。
5. 任一路 FIFO 满只反压对应核；不得丢弃已成交 flit，也不得把部分和排入 L2 单写口。

## 5. 未决项

| 项目 | 当前处理 | 冻结门槛 |
|---|---|---|
| lane 数 | 参考 16 lane，不硬编码 | 吞吐和面积核算 |
| FIFO 深度 | 16 条仅作参考默认值；实际深度参数化（HUB_RHUB §5.4/§7） | RTT、反压和宏观 RF 仿真 |
| 入口/量化流水级数 | 默认对齐 1 拍、两级加法各 2 拍、量化 2–3 拍、总延迟不超过 10 拍【待标定】 | 周期级仿真和时序收敛 |
| 精度验收线 | 目标与 FP32 精确和再量化对比 | 软仿硬链标定 |
| 精度目标 | 一致比例目标 ≥99.9%，不一致处最大差 1 码【待标定】 | 参考模型、硬件回归和误差统计闭环 |
| 面积目标 | 约 0.084 mm²、48 个 BF16 加法器、2,080 B RF【一阶推导】 | 工艺映射和 lane 数冻结 |
| MiniCPM 旧 VC2 口径 | 保留兼容字段，暂不启用 | 数据流篇审查 |
| down/o K 切分 | 默认关闭 | 容量和调用场景审查 |
| PDF lane 数冲突 | 图注写 32 lane，正文参考设计写 16 lane；当前按参数保留 | 架构评审关闭冲突 |
