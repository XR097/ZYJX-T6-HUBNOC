# R-hub 周期级时序与状态机

本文件定义 R-hub 的周期级合同。`C0` 表示当前时钟边界；所有 `fire` 事件只在相应 valid、空间和配置条件同时满足时发生。具体流水级数用参数表示，不把建议值写成固定 RTL 延迟。

## 1. 流水阶段和最小控制状态

R-hub 是连续 valid/ready 流水，不是“收一组、发一组”的串行 FSM。四路对齐、两级加法、组缓存和量化可以同时占用不同条目；输出回压时只冻结输出保持槽及其上游占用槽，已有前级空间的条目继续推进。每个参与核的 FIFO 只在 `align_valid && align_ready` 时弹出。

| 阶段/状态 | 进入条件 | 动作 | 退出条件 |
|---|---|---|---|
| `DISABLED` | `enable=0` 或非 R-hub 位点 | 不接收 VC2 部分和，输出空闲 | GO 后 `enable=1` |
| `WAIT_HEAD` | 对齐器等待参与核头部 | 检查参与掩码对应 FIFO | 头部齐备且 `add_ready` 有效时产生 `align_valid` |
| `ALIGN_FIRE` | `align_valid && add_ready` | 同拍消费每个参与核一个 flit，产生每路 pop | 下一周期可继续接收，或因任一 ready 为 0 暂停 |
| `ADD_PIPE` | `ALIGN_FIRE` 成交 | 固定两级 BF16 RNE，允许每拍接受一条 16 元素条目 | `L_add` 拍后产生 result |
| `GROUP_PHASE` | result 到达 | `phase=0` 写入 32 B 第一条缓存；`phase=1` 与缓存拼组 | 第一条进入缓存或第二条进入量化 |
| `QUANT_PIPE` | 两条相邻结果有效 | amax、E8M0、E2M3 编码、RNE 和限幅 | `L_quant` 拍后写入输出保持寄存器 |
| `EMIT_STALL` | 输出保持寄存器有效但 VC2 无信用 | 保持 payload、owner、序号和 sideband | 下游允许发送 |
| `EMIT_FIRE` | 输出保持寄存器和下游均有效 | 发送一次回送 flit，释放该输出槽 | 下一条已就绪条目可继续进入流水 |

`WAIT_HEAD` 不因单路到达就消费。R-hub 不负责检测 pid 顺序；pid 顺序错误属于核侧出口队列/CCU_CTL 合同违约，应在系统验证中注入并观察错误归属（HUB_RHUB §2.2、§4.2.1）。协议字段检查和 VC 分流由 HUB-UP/HUB-DN 完成；R-hub 内部保留断言即可。

## 2. 正常单条目时序

设 `L_align=1`、`L_add` 和 `L_quant` 为实现参数，单条 16 元素输入的抽象时序如下：

| 周期 | 事件 | 必须保持的条件 |
|---|---|---|
| C0 | 四路参与 FIFO 头部齐备 | 参与掩码有效且加法流水可接收 |
| C1 | `ALIGN_FIRE`，四路各弹出 1 flit | 同一 pid 序；pop 事件交给 HUB-UP 产生下一拍返还；下一条可在下一拍对齐 |
| C1～C1+`L_add` | `ADD_PIPE` | 固定两级加法；流水可以继续接受后续条目 |
| C1+`L_add` | 得到 16 个 BF16 结果 | 组相位决定进入缓存或量化 |
| 后续 | `HOLD_FIRST` 或 `QUANT_PIPE` | 第一条结果不可覆盖；量化输入必须是同一归约流中相邻两条 |
| 完成后 | `EMIT_STALL/EMIT_FIRE` | `group_seq`、owner 和 payload 保持到一次成交 |

参考时钟预算为入口对齐约 1 拍、加法与量化各若干拍；最终值由阶段二仿真和实现时序冻结（HUB_RHUB §5.4，PDF 第 6 页）。

## 3. 两条结果拼组时序

1. 第一条结果 `result_phase=0` 成交后写入 `group_buffer[31:0]`，锁存组相位/属主上下文并将相位置 1。
2. 第二条结果必须按核侧保证的下一 pid 顺序到达；R-hub 不读取 token 标签，对齐后进入量化流水。
3. 量化器将缓存的 16 元素和当前 16 元素拼为 32 元素，求共享 `amax`，生成 E8M0，再编码为 E2M3 g32。
4. 输出组序号使用归约属主核对应的 16 bit 计数器；计数器清零时机仍待审查。序号与 25 B 载荷一起锁存。
5. 输出成交后清除 `group_buffer`，相位回到 0；若输出被阻塞，缓存和量化结果均保持不变。

## 4. 回压和信用时序

### 4.1 输入 FIFO 回压

- 某一路 FIFO 满时，由 HUB-UP 撤销该核对应的上行 VC2 信用；R-hub 只产生该路 pop 事件，不能直接驱动协议返还线。其他核仍可入 FIFO。
- `ALIGN_FIRE` 需要参与核头部同时有效。非参与核按配置视为 0，不读取其 FIFO。
- FIFO 弹出发生在 `ALIGN_FIRE`；信用返还在协议 B 规定的下一拍脉冲返回核侧。
- 输入 FIFO 与 L2 单写口分离，R-hub 回压不占用 HUB-UP 的 L2 写口队列。

### 4.2 输出回压

- HUB-DN VC2 无可用信用时进入 `STALL`，保持 payload、`group_seq`、owner 和 sideband 不变。
- `EMIT` 未成交前不得清除量化结果、推进组序号或重新使用 `group_buffer`。
- 输出恢复后只允许发送一次，避免重复回送；HUB-DN 负责具体道选择和多播完成配对。

## 5. 错误和边界行为

| 场景 | R-hub 行为 | 归属 |
|---|---|---|
| 上行 `vc != 2` 或类别非法 | 不应进入 R-hub；由 HUB-UP/协议检查器锁存并上报 | 协议 B/HUB-UP |
| `nw8` 非法或非末拍不满 4 字 | 不应进入 R-hub；由协议检查器锁存并上报 | 协议 B |
| 参与核 pid 顺序错误 | R-hub 不匹配标签；系统验证报告数据合同违约 | CCU_CTL/E6/核侧出口 |
| FIFO 满 | 对应核信用反压，计流量性停顿 | R-hub ingress |
| 输出 VC2 堵塞 | `STALL` 保持，计流量性停顿 | HUB-DN/R-hub egress |
| 第一条结果等待过久 | 由位点/看门狗策略决定；R-hub 不自行推断 token 超时 | LIC/调用控制 |
| 组相位或 owner 配置冲突 | 停止产生新输出并上报控制错误 | 描述符/LIC |

## 6. 必备断言与覆盖

### 断言

- FIFO 不能下溢/上溢；信用不能小于 0 或超过初值。
- `ALIGN_FIRE` 只在所有参与核头部有效、且下游流水有空间时发生。
- 每次 `ALIGN_FIRE` 每个参与核恰好弹出一个 flit。
- 加法树固定为 `(c0+c1)` 与 `(c2+c3)` 后再相加，且每级使用 BF16 RNE。
- `HOLD_FIRST` 有效时禁止覆盖第一条结果。
- 输出阻塞时 payload、sideband、owner 和 `group_seq` 保持稳定。
- 输出成交后同一个 `group_seq` 不得再次发送；输出保持槽有空位时，前级流水允许继续填充。
- 输出 VC/class/owner 与配置一致；R-hub 不产生 L2 地址。
- `ALIGN_FIRE` 的最大接收率为每拍一条 16 元素条目；在参考 16 lane 配置下两拍形成一组，前级和输出保持槽不得把吞吐降成“每组完成后才接收”。

### 覆盖

- 四路同步到达、逐路错拍和任一路长时间回压。
- 参与核掩码为 1～4 路、缺位按 +0 的归约。
- 第一条/第二条拼组跨越输出阻塞。
- amax 为零、正常值、最大值、量化边界和限幅值。
- owner=0～3 的回送路由和组序号回绕。
- reset/GO 切换、非法 sideband、FIFO 满和协议错误上报。

## 7. 规格未决项

lane 数、FIFO 深度、`L_align/L_add/L_quant`、精度验收线、down/o K 切分条件以及面积预算继续引用 `HUB_RHUB.pdf` §7（PDF 第 7 页）。参考默认值为对齐 1 拍、两级加法各 2 拍、量化 2–3 拍、到齐至回送不超过 10 拍【待标定】；这些值进入配置/验证矩阵后再冻结。PDF 图注的“32 lane”和正文的“16 lane 参考设计”存在冲突，必须在架构评审中单独关闭。
