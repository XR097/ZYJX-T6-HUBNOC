# 验证计划

## 断言清单

### 协议与信用

- 信用不能下溢或超过初始化深度；信用为零时禁止发送。
- FIFO 满时禁止写入；返还脉冲只能在接收端实际弹出后产生。
- 下行非末拍 `nw8=4`；末拍 `nw8` 在合法范围内；`last` 与传输单位边界一致。
- VC0/VC1 按核、VC、道隔离；VC2/VC3 的同拍限速必须按 `05_open_issues.md` 的协议裁定检查（HUB_NOC 为“各 1”，协议总规范为“合计 1”）。
- 多播发送必须同时满足所有目的端信用；末 flit 只有全部目的端返还后才能触发 `RCNT`。

### HUB-UP / ATT / SYNC

- 同一核+区域的写游标只前进、正确回绕，区域之间不能串写。
- L2 `WCNT` 只能由真正落 bank 的写仲裁更新，HUB 不重复计数。
- ATT 合并键未收齐时不得输出；环满时必须反压；广播目的只能来自参与掩码。
- SYNC barrier 只在参与核全部完成、位点号和计数匹配后发 GO；GO 后一个周期生效；超时必须上报 LIC。

### R-hub

- 四路 FIFO 头部未齐时不出结果；任一路满只反压对应上行源。
- 加法树固定为两级 BF16 RNE，结果与到达次序、回压和综合调度无关。
- 第一条 16 元素结果必须保留，第二条到齐后才能计算 32 元素 `amax` 和量化。
- MXFP6 E8M0、6 bit 编码、RNE、限幅、16 bit 组序号和归约属主号必须与参考模型逐位一致；量化点与后处理单元的同类量化点逐位一致。

## 定向测试

| 组别 | 场景 | 主要检查 |
|---|---|---|
| DN | 单播、四核多播、控制优先、数据 VC 保底 | 顺序、信用、目的掩码、RCNT |
| DN | 任一道信用耗尽、返还延迟、末拍部分有效 | 局部反压和 `last/nw8` |
| UP | 四核同时区域写、列表环写、环满 | 有界仲裁、游标和 WCNT |
| ATT | 2/3/4 核位图收齐、缺核、多个在飞 tile | OR 键、到齐位、广播 |
| SYNC | 标量乱序到达、barrier 缺核、错位点号、超时 | 固定合并顺序和 GO |
| R-hub | 四路不同到达顺序、单路回压、FIFO 满 | 逐位归约和局部反压 |
| R-hub | 单条/两条成组、极值/零/非正规数 | 组缓存、amax、量化 |

## 端到端场景

1. **Prefill**：D-40 激活多播 → 上行 VC1 写 L2 → K 切分 VC2 → R-hub → D-40 VC2 回送；属主核产生的 K 切分判决经 HUB-ATT 按掩码 VC3 广播 → barrier/GO。
2. **Verify**：2～3 核录取/区块位图 → HUB-ATT OR → 列表环写 → SYNC 位点交接；不引入 Prefill 的 K 切分判决广播。
3. **Decode**：单核单播重放、最小同步路径、无 R-hub 负载，检查退化场景下的信用和完成语义。

每项测试记录仿真器版本、随机种子、配置参数、波形检查点和结果；正式覆盖率目标待验证环境建立后补入。
