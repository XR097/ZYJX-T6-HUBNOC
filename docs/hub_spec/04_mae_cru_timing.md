# MAE_CRU 端到端时序

> 本文件按责任方整理 `L2 → MAE_CRU → L2` 的阶段。各阶段可流水重叠，内部实现由设计者确定；不要求串行状态机。

## 1 阶段与责任

| 阶段 | 责任方 | 现行行为与依据 |
|---|---|---|
| 产出写入及报告 | 各核 CCU、L2 | CCU 经 C2H 写本核象限，数满 L2 写入握手后发出报告（MAE_CRU §4.2） |
| 报告配对与放行 | MAE_ENG | 按报告目的起始地址配给合并指令，收齐参与核报告后执行；CRU 不持报告等待状态（MAE_CRU §1.2、§4.2） |
| 发读与控制 | 搬运引擎、NI_INT | 引擎给参数和逐拍源/目的地址；归约读四象限同址，残差加分拍读两路地址（MAE_CRU §2.1） |
| 对齐、合并、编码 | MAE_CRU | 参与份对齐后按固定象限次序合并并编码；对齐方式和内部流水由设计者定（MAE_CRU §3、§4.1、§6.2） |
| 结果交出 | MAE_CRU、NI-L2C | 每拍结果经 NI-L2C 写客户写回 L2；CRU 报告本条指令的结果全部交出，压缩时随结果交实际字节数及 tokmax（MAE_CRU §2.1、§5） |
| 写入完成 | 搬运引擎、L2 | L2 最终落 bank 后返回带 src 的写入握手，引擎只计自己的握手；压缩输出的 token 长度表由引擎写入（MAE_CRU §5.3、§5.6） |
| 指令完成及依赖 | MAE_ENG、LIC | MAE 带指令标号通知 LIC；LIC 据此下发依赖指令，包括下一条残差加及后续 H2C 搬运（MAE_ENG §9.4、§10.2–§10.3） |

CRU 的结果交出与引擎判断的目的写入完成是两个时刻。报告收集、最终写入计数和 LIC 依赖调度不属于 CRU 的合并流水。

## 2 读返回与对齐

NI 读口为 4 × 32 B，每象限一份。归约、标量合并和读集合并按四象限同址读取，某象限 busy 可使该份顺延。CRU 只等待当前地址的参与份，掩码外象限不等待；进入合并的数据必须属于同一个象限内地址。每象限小 FIFO 或其他对齐方式由设计者定（MAE_CRU §4.1）。

残差加的两路加数分别来自归约结果对象和残差流对象，由引擎按各自地址分拍读入；CRU 对齐同一 token 的同一通道段后相加。第一条归约写入完成后，LIC 才下发第二条残差加；分块流式时由 Fusion-L3PU 段按块循环（MAE_CRU §3.1a；MAE_ENG §9.4）。

份数超过四份的支持范围由设计者定；若支持，额外份由引擎给地址多读几拍，累加次序必须固定（MAE_CRU §3.4）。

## 3 流水、反压与顺序

读入与写出每段都是 ready 握手，任一段 ready 低时执行引擎统一停发。输出数据及地址、be、src 在停顿期间保持；恢复后继续，不丢、不重（MAE_CRU §6.1；传输协议 §3.3）。

无 bank 冲突且下游可接收时，流水必须跟得上每拍四份读入、每拍一个 32 B 结果写出；解码、编码及按列表压缩不得降低正文规定的速率，压缩后不足一字时按输入侧每拍一字计。各阶段不得被本文件理解为“一地址完成后才处理下一地址”的串行 FSM（MAE_CRU §6.2）。

同一链路保序；合并点只在单位边界切换源、单位内各拍不交错，不要求一条多单位指令独占整条链路（传输协议 §3.9；MAE_ENG §8）。

## 4 完成、复位与验证边界

L2 的写入握手只在实际落 bank 后产生。搬运引擎以本指令应写量比对自己的 src 握手，写入完成后通知 LIC；CRU 不能用固定时延代替该判据，也不等待这些握手才处理下一结果拍（MAE_CRU §2.1、§5.3；传输协议 §3.8）。

复位清 CRU 在途读入和在途合并；CRU 不做运行时检查，不设置本文件新增的 ERROR 状态。编码、列表和地址对应关系作为验证断言检查；既有硬件错误范围及归属遵循主文档（MAE_CRU §7；MAE_ENG §13.1；传输协议 §9）。
