## 2 条目

### 2.1 来自 DATA_TRANSFER_PROTOCOL

- **CI-S-01** **写 MUX 与来源之间的接口：写请求、选择与选中**（来自协议篇源 §5.2 写口两侧接口表；L1_LANDING_BRIDGE 源 §2.3、§11.1 BRG-R4；架构篇源 §3.2 末段；V18-VNU-09 / L1-24；分层清单接收桥 D3、清单 §D.3 接收桥 D3，用户"集成篇任务"）：写请求（来源 → 写 MUX，每来源一组）= 请求有效、`seg` 5 bit、首字节地址（24 bit，VNU 写口的由 CCU 按计数推出，接收桥的由到达的 addr）、有效字节（len 或 be，形式【设计者定】）、从第 0 字节起首尾相接的 ≤ 128 B 数据；接收桥源稿另有**道号**（H2C 接收桥 2 bit，NWB 恒 0）与**拍数**（2 bit，本请求含 1–4 个写入拍；默认就是存储字数；S 类恒 1；握手计数器按它加），是否需要这两个字段由计算核集成定。**写 MUX 不由 CCU 逐拍选来源：在三个来源之间按固定规则自己轮流，没轮到的在自己的 FIFO 里等；写与读碰到同一个堆时写让读、本地判断**（第三轮，V18-L1-32；原"选择（CCU → 写 MUX，每类每拍）"一组线撤）。选中（写 MUX → 来源，每来源 1 位）对应本拍交出的请求，另带本次写进的拍数，形式【设计者定】：要定的是拍数随选中回还是由来源按自己交出的请求推出；约束是选中对应本拍交出的请求、请求的字节要么全部写进要么都不写，来源出队与握手计数器所加的拍数和写进 L1 的拍数一致。核内写 L1 的完成由 CCU 判定，L1 不提供完成信号；**VNU 写的完成由写 MUX 告知 CCU 或由 VNU 报完成【设计者定】**（V18-L1-32 (3)，VNU 集成篇 §2.6.3）。**VNU 写口一次写的地址与 `seg` 由 CCU 计数推出、数据与有效字节由 VNU 交；两者在哪里拼成一次写【设计者定】——地址随 VNU 的写一起进 VNU 写口的 FIFO，还是在写 MUX 处与数据汇合；约束：一次写的地址、`seg`、有效字节与数据一一对应，不丢、不错位**（VNU 集成篇 §2.6.1，协调会话 11-11 裁定第 3 条）。（原写法"写 MUX 由本核 CCU 控制，选中 VNU 写口的那一拍数据即写进 L1"被 V18-L1-32 取代。）
- **CI-S-02** **集成输出端口的发送 FIFO**（来自协议篇源 §7.1；架构篇源 §2.3 小存储表"集成输出端口发送 FIFO"行、§3.4 FIFO 行；V18-TP-56）：待上 C2H 的 addr / data / en 三条同步 FIFO；入口每拍至多收 4 个存储字（128 B，A 类读 MUX 或 S 类读 MUX 整拍交来的读出），出口每拍一个存储字（32 B）上 C2H；MXU、VNU 输出直接出核同样进这个 FIFO。深度【设计者定】：> CCU 停算到最后一拍进 FIFO 的在途拍数 $L$，将满阈值 = 深度 − $L$；将满时拉 stall_tx 门控 CCU（停发全部 en、停算，等 C2H ready），这是核内唯一的全局门控。
- **CI-S-03** **L1 外四个 MUX 的内部实现；A / S 类读 MUX 不排字序、不移位**（来自协议篇源 §5.3 表；架构篇源 §1.4、§3 引言；V18-L1-21 / 24）：写 MUX、A 类读 MUX、S 类读 MUX、W 类读出到 VNU 读口的一路的内部实现归计算核集成；**写 MUX 不由 CCU 逐拍选来源：在 H2C 接收桥、NWB、VNU 写口三个来源之间按固定规则自己轮流，没轮到的在自己的 FIFO 里等；写与读碰到同一个堆时写让读、本地判断；A 类读 MUX、S 类读 MUX、W 类读出到 VNU 的一路与计算核输出口四处仍由 CCU 定去向**（第三轮，V18-L1-32）；A / S 类读 MUX 只选使用者，整拍交 CCU 指定的一个使用者入口；对外的每拍规则见架构篇 §3.7。

### 2.3 来自 L1_SRAM

- **CI-S-06** **发送侧：出核读与集成输出端口**（来自 L1_SRAM 源 §8 引言、§8.1、§8.2；V18-TP-35 / 56 / 59 / CRU-07 / L2-04 / TP-57 / 61 / 32 / 38）：核内单元不直连 C2H，要出核的数据先写进 L1，再由 CCU 按发送指令读出、配上逐拍地址送上 C2H；读出经 L1 外的 A 类读 MUX（或 S 类读 MUX）整拍交**发送 FIFO 入口**（128 B，集成输出端口的发送 FIFO 入口，不是 L1 的口）。C2H 由本核 CCU 发令，发送是位点指令的一部分；发送指令字段：源（本核 L1 的数据块：堆选、类选、起始地址）、目的（L2 目的地址，C2H 只到 L2）、长度（存储字数；码块的总字数 = 各通道片码块片长之和、F 列表的总字数 = 各片 F 列表片长之和；元数据项、E8M0 项、F 列表、码块各按自己的源地址发出）；没有请求号等回报字段，字段位宽归 ISA。计算核的集成输出端口是 C2H 的唯一来源：L1 发送读出、VNU 输出口（含经 EPI 透传的 MXU 输出）由本核 CCU 按指令选一路、只在切换段边界切换。读出的存储字进集成输出端口的发送 FIFO（深度【设计者定】），配上 CCU 逐拍给出的 addr 发上 C2H，端口不累加地址；读出的字数与给出的拍数都等于发送指令的数据量，由 CCU 保证一致。本核 C2H 只写 L2 象限 $n$。C2H 的 addr 24 bit 段内地址，另带 `seg` 5 bit、be 与 `src`。发送 FIFO 将满（深度 − $L$，$L$ = CCU 停算到最后一拍进 FIFO 的流水深度【设计者定】）时拉 stall_tx 给 CCU，CCU 被门控、停算，等 ready 恢复再继续（用户 11-07："C2H 不 Ready 时，CCU 需要被 Gating 住，等待 C2H Ready 再继续计算数据"）；端口的 en、din、be、addr、`src` 全部寄存器输出、出口配 skid，ready 为 0 时原样保持本拍（端口是 HUB 提供的通用链路块的实例）。用户 11-06："要么就取消 C2H 的 MAE 主，统一改成各核的 CCU 主"；11-07："对于 C2H 口，它只有一个来源，即 CC 的集成输出端口，在 CC 内部，由 CCU 来控制数据来源"。
- **CI-S-07** **MXU、VNU 的输出写 L1 或直接写 L2，二选一**（来自 L1_SRAM 源 §8.3；V18-TP-56 / 59 / EPI-01）：每条指令由 CCU 选写 L1（经 VNU 写口）或直接写 L2（经 VNU 输出口、集成输出端口上 C2H，每拍 L2 地址由 CCU 推算），不支持两边都写；MXU 组到 AEB 为止，MXU 输出先经 EPI 处理或透传；直接写 L2 时 C2H 停顿经 stall_tx 门控 CCU，只写 L1 时不受 C2H 影响；C2H 每核 32 B/拍，输出速率高于它的位点由编译链选写 L1。用户 11-07："VNU 和 MXU 的输出可以由 CCU 直接推算要写在 L2 SRAM 的地址，然后走核间协议，不过也要支持输出写回到 L1 SRAM"；"不要支持两边都写，只能支持写 L1 或者写 L2"。
- **CI-S-08** **跨核合并与标量都走数据协议、经 L2**（来自 L1_SRAM 源 §8.4；V18-CRU-07 / TP-55）：K 切分的部分和、读集合并的位图、要跨核合并的标量（$(m_{\text{run}}, l)$、归一化平方和部分和、$\sum g^2$ 部分和、量化的跨核 amax 部分值）由本核写进 L2 象限 $n$ 的同一段内地址（同址异象限），MAE 收齐参与核的发出报告后由 MAE_CRU 读四个象限、合并、写回 L2；不经 CCU 中转、不走命令网；合并值经 L2 → H2C 落 L1 后由 VNU 从 L1 读。用户 11-07："如果这些标量走的仍然是核间通信协议，那我认为他们也要存在 L2 SRAM"。
- **CI-S-09** **发送完成与写入完成由 CCU 计数、写入握手数满后 CCU 发出报告**（来自 L1_SRAM 源 §8.5；V18-TP-35 / 47 / MAE-14 / TP-49 / DORG-05 (8)）：L1 不向 MAE 报完成；本核 CCU 按发送指令的数据量数自己给出的拍，数到即"发送完成"；再数满 L2 沿 C2H 反向回来的写入握手（每写进一个写入拍一个）即"已写进 L2"，之后经发出报告专用信号组（本核 CCU → MAE，不经命令网）发出报告（只带目的起始地址，紧凑 token 记录取码块的容量窗口基址；MAE 按目的起始地址把报告配给源起始地址相同的那条指令）。判据里没有时延常数；跨核合并何时可做由 MAE 按收齐的发出报告判定。
- **CI-S-10** **四个 MUX 与 L1 的衔接**（来自 L1_SRAM 源 §2、§6.4、§12；V18-L1-21 / 24）：写 MUX 每拍为每类写口选一个来源的一次请求（至多 128 B），三个来源之间按固定规则轮流、写让读（第三轮，V18-L1-32）；VNU 写口的写何时写进由写 MUX 告知 CCU 或由 VNU 报完成【设计者定】；未选中的来源：接收桥的请求不丢、之后再交、等待有上界（怎样再交见接收桥篇第 7 章，V18-TP-84 (7)），收不下时拉低核间 ready；VNU 写口的请求在 VNU 一侧保持、来不及时对 VNU 各单元拉 wr_stall；多播时各目的核独立取走，慢核落后不超过 $M_{\text{mc}}$ 拍不拖其他核，超过时只降速、不丢（余量由接收桥提供，见接收桥篇、HUB_NOC 篇）。来源没轮到而等待的拍数、各使用者占用读拍的统计（性能计数，参考实现）在读写 MUX 一侧。

### 2.5 来自第三轮同步（MXU 四篇、VNU_CONTROLLER、CIF 定稿之后）

- **CI-S-14** **写 MUX 自己轮流、写让读，不看位点状态**（来自 L1_LANDING_BRIDGE V1.8 §1、§3.5、§3.6、§5.2；V18-L1-32、V18-TP-70；接替撤掉的 CCU-S-14 / 15）：写 MUX 每类写口每拍在 H2C 接收桥、NWB、VNU 写口三个来源之间按固定规则轮流选一个，没轮到的在自己的 FIFO 里等；写与读碰到同一个堆时写让读，本地判断，CCU 不参与；**轮流时不看消费者的位点指令是否已装入**（接收桥常开，数据可以先于位点指令落地，等位点会让先到的数据堵在接收桥、经 ready 反压上游）。轮流规则与 $W_{\text{wait}}$（写 MUX 连续不选某一来源的最长拍数，接收桥篇 §1 定义）由计算核集成设计者登记；目的堆被读长时间占用时只降速、不丢数。**写让读之后写的等待没有由 CCU 排法给出的上界，是否需要 CCU 一侧对同一个堆的连续读加限制【待确认】**（T1 报告 §3 第 3 条、T2 报告 §3）。
- **CI-S-15** **核内三个控制器的关系；停止请求在核内只到 CCU**（来自同步清单 §一第 1–4 条、§三；架构篇 §3.2、§2.7.7；CIF 篇 §2.4 / §2.6；V18-MXU-19 / 20 / 22、V18-VNU-11 / 12、V18-CCU-01、V18-CIF-04）：核内有三个控制器：**CCU（发令方：L1 的全部读地址与 VNU 写回地址只有 CCU 一个来源，A / S 类读出、W 类读出到 VNU 的一路、计算核输出口的去向由 CCU 定）**、**MXU_CONTROLLER**、**VNU_CONTROLLER**（按 CCU 给的配置与脉冲做模块内部逐拍的控制：内部缓冲的位置、处理先后、握手；不是发令方，不产生 L1 地址）。CCU 给两个控制器的形式见 `CCU_STAGING.md` CCU-S-74。复位：MXU、VNU、L1、接收桥只收 CIF 的复位（不区分硬 / 软），没有启动输入；**停止请求在核内只到 CCU**，CCU 停发后 MXU、VNU 把已收到的数据做完、停在原地，继续送后不丢、不重。
- **CI-S-16** **核内到 CCU 的停顿信号**（来自 MXU 集成篇 §2.8、VNU_CONTROLLER 篇 §2.7、协议篇 §2.4 / §3.16；V18-MXU-17）：stall_mxu 每 pod 两根（权重缓冲收不下、激活缓冲收不下），CCU 只停发给这个 pod 的对应读；stall_vnu 一根（VNU 读入口来不及收）；stall_tx 一根（集成输出端口发送 FIFO 将满，见 CI-S-02，核内唯一的全局门控）。wr_stall 只在 VNU 写口与 VNU 单元之间，不到 CCU。阈值都按在途拍数定。
