### 2.1 来自 DATA_ORGANIZATION

- **CCU-S-01** **CCU 是 A 类读 MUX 的一个使用者，带收元数据项与 F 列表的 ping-pong 预取缓冲**（来自 DATA_ORGANIZATION 源 §2.6.3 第 1 条、§2.2；协议篇源 §5.3 A 类读 MUX 使用者表 CCU 行；L1_SRAM 源 §2.3、§3.5；架构篇源 §2.3 小存储表"CCU 预取缓冲"行、§3.1.2 CCU 行、FIG-TP-ARCH-INCORE 说明；TRANSFER_DATA_REGISTRY 源 REG-13 / REG-22 / REG-32；V18-L1-20 / 21）：CCU 入口 128 B，从 A 类读 MUX 收；ping-pong 两半，一半供当前批解码，另一半在 A 类读出空闲的拍里预取下一批各 token 首片的元数据项首字与 F 列表首字，换批时不等元数据（不预取时换批约多 3 拍气泡）。【设计者定】要定的是每半的字数与预取深度，参考每半 = 每 token 2 个存储字 × 一批 token 数（32 个 token 时 $2 \times 32 \times 32 = 2{,}048$ B，约 2 KB）；约束是换批时下一批首片的元数据已在缓冲里，计入 CCU 的存储账。理由：激活驻留时 pod 计算期间 A 类读出基本空闲，预取消除换批等待。用户 11-09："我支持元数据放回A类，CCU增加ping-pong预取缓冲"。
- **CCU-S-02** **顺序消费与组内随机读时的定位方式**（来自 DATA_ORGANIZATION 源 §2.4；DATA_ORGANIZATION V1.8 §3.2 末段（第二轮回改，原 CCU-S-61；A4 / 清单 O9））：顺序消费（pod 流式读一个 token 组，前向与反传相同）时 CCU 读元数据项，两个游标分别累加码块片长与按字取整的 F 列表片长；组内随机读（CCU_GRP 把一组 32 个 token 按码数排序后发给 4 个 pod）时 CCU 先读该组各通道片的元数据项再定位，定位方式由 CCU 定。
- **CCU-S-03** **旁带的物理通路与跨界字交接**（来自源 §2.6.3 第 5 条；V18-DORG-05；V18-NAME-08）：每个发读步长随码字交 pod 的旁带 = keep 掩码 128 bit + F 掩码 128 bit + MX 组边界 + 首字起始位偏移；物理通路与位宽【设计者定】（与 MXU 共同定）。发读步长的码起止位落在存储字内时跨界那个字怎样交接（读一次、两个发读步长共用，或重读）【设计者定】，约束是节拍由 CCU 事先算定、不靠 pod 反压。**【待确认】（第三轮）**：MXU 集成篇 §2.3.1 / §2.5.3 写的是"码从通道片的码块起点起首尾相接到达、MXU_CONTROLLER 按保留位图 1 的个数乘 $w$ 自己数"，旁带只列保留位图、F 掩码、MX 组边界，没有"首字起始位偏移"；按那里的写法，跨界的存储字只送一次、起始位偏移不必另给。本条与数据组织篇 §3.4.3 的旁带定义要不要随之删掉"首字起始位偏移"、跨界字是否只送一次，由 CCU 与 MXU 设计者对接，交协调会话定。
- **CCU-S-04** **用整行统计量判决的位点清单**（来自 DATA_ORGANIZATION 源 §4.8.3、§5.7；VNU_QNT 源 §3.7；VNU_SEL 源 §3.3；V18-DORG-08，用户 11-05）：相对阈值、QDS 行均值等用整行统计量判决的位点不支持按通道片分段流水；在权重驻留下判决前的值须先以 BF16 写 L1、整行判完（行统计就绪、SEL 给出判决位）后 QNT 再读回压紧与量化（数据组织篇 §3.5.3、§3.6.8）；哪些位点如此，由 CCU 按 SEL 的选择模式逐位点列出。
- **CCU-S-05** **分批搬运时发出报告带流标号**（来自 DATA_ORGANIZATION（V18-MAE-45 (1)）；协议篇（§3.8 / §3.13）；MAE_ENG 源 §5.10 / §10.4；V18-MAE-45 (1)）：分批搬运时 MAE 记游标、跨指令续接起点，下一批指令里没有实际起点；CCU 经发出报告专用信号组（架构篇 PORT-39）给 MAE 的报告除目的起始地址（码块的容量窗口基址）外另带流标号，MAE 按（目的起始地址, 流标号）把报告配到对应的流与指令，用于游标续接；流标号的位宽与编号方式由 CCU 与 MAE 设计者对接（ISA 登记）。

### 2.4 来自 L1_SRAM

- **CCU-S-16** 内容已并入 **CCU-S-01**（合并重复条目，来源列在该条）。
- **CCU-S-17** **CCU 读一条紧凑 token 记录交 pod 的步骤：按元数据项定位每一片、算各发读步长的码字、发读与旁带**（来自 L1_SRAM 源 §3.5；MAE_ENG 源 §5.9 M-1a / §10.4；架构篇源 §3.1.2 第二条；V18-L1-20 / DORG-05 (3) / DORG-10 / MAE-36 / TP-69 / MAE-42；第二轮回改并入三份同一件事：DATA_ORGANIZATION V1.8 §3.4.3 第 1–5、7 步（原 CCU-S-58，D9；V18-TP-65 / L1-21）、DATA_TRANSFER_PROTOCOL V1.8 §3.13"消费方读紧凑 token 记录"段（原 CCU-S-62；V18-TP-66 / 74）、L1_SRAM V1.8 §2.5.1"紧凑 token 记录的读法"（原 CCU-S-66；A4 / A14，清单 L1 O3））：解码由 CCU 承担，发读节拍全由 CCU 事先确定、不靠 pod 反压。
  1. **定位与读元数据**：第 $q$ 个通道片（$q$ = token 号 × 每 token 片数 + 片号）的定位按数据组织篇 §3.2（元数据项 = 基址 + $q$ × 项宽；E8M0 项 = 基址 + $q \times \lceil (P/G)/32 \rceil \times 32$；F 列表与码块 = 基址 + 前面各片片长之和）。CCU 是 A 类读 MUX 的一个使用者，轮到 CCU 的拍里的一次 A 类读（首地址 + 长度 ≤ 128 B，L1 交回从第 0 字节起按地址对齐好的数据）进 CCU，读该片的元数据项与 F 列表；参考做法是超前一个通道片读，与本片码的读出流水；CCU 一侧收元数据的缓冲与换批预取见 CCU-S-01。
  2. **算节拍**：keep 位图每 32 个通道一个 32 bit 字段，popcount 得这 32 个通道的码数；一个发读步长（定义见 CCU-S-57）= 128 个归约位置（压紧前），该步长的码数 = 4 个字段 popcount 之和，码的位数 = 码数 × $w$；由此算出这个发读步长的码在码块里的起止位、要读的存储字与第一个字里的起始位偏移。
  3. **转掩码**：把 F 列表的片内序号转成每个发读步长一个 128 bit 的 F 掩码（位 $i$ = 1 表示该通道要读 lo 平面；即每 32 通道一段、四段拼成，原 CCU-S-62 写作"每 32 通道的 F 掩码"，与此同义）。
  4. **读尺度**：CCU 发 S 类读，本发读步长用到的 E8M0（每 $G$ 个通道一个）经 S 类读 MUX 直接进 pod 的激活旁带，不经 CCU。
  5. **发读与旁带**：按算好的存储字地址发 A 类读，码字经 A 类读 MUX 交 MXU（带 pod 号与有效字节数；源属于哪个 pod 是固定的，CCU 对每个 pod 按"片为主序、片内源的序号从小到大"推送，不带源序号、不设结束脉冲，MXU 集成篇 §2.3.2、MXU_CONTROLLER 篇 §3.2，V18-MXU-24 / 25）；pod 入口 1 道 128 B，CCU 分时给各 pod 压入不同 token（CCU-S-11）。每个发读步长随码字交 pod 的旁带 = keep 掩码 128 bit + F 掩码 128 bit + MX 组边界 + 首字起始位偏移（旁带内容是数据组织篇 §3.4.3 的约定；物理通路与跨界字交接见 CCU-S-03）。旁带、E8M0 与码字的先后与保持归 CCU 与 MXU 设计者（V18-EPI-05 / TP-83 同理，不作需求）。
  6. **读写带宽**：CCU 读元数据的拍、给 pod 读码的拍、VNU 与发送 FIFO 入口读的拍都由 CCU 排进 A 类读出；编译链不做读写带宽保证，需求超出时使用者自己等。
  7. **跨核数据要等写完通知**：从别的核或 L2 落进本核的数据，CCU 收到 MAE 的写完通知（目的基址 = 码块的目的基址、字数 = 四块之和）之后才读它的元数据项，不边到边读；按照抄过来的元数据项顺序累加码块片长与 F 项数定位每一片，其余三块的位置由 CCU 按元数据项推出（数据组织篇 §3.4）；按批流水时按批判（LIC 的 Fusion 段里每批是一条搬运指令的一次执行、各发一次写完通知）。顺序读时 CCU 的游标逐片推进；组内随机读先读该组的元数据项再定位（见 CCU-S-02）。
- **CCU-S-18** **CCU 的核内地址生成与环形回绕**（来自 L1_SRAM 源 §3.3；V18-MAE-17）：CCU 从指令取一个基址（字节），每交出一个存储字加 32，隔字取用时步长可配（字节，32 的倍数）；码块里一个通道片占 $\lceil n_i/32 \rceil$ 个存储字（$n_i$ 为该片码字节数），下一片从下一个字开始，CCU 按元数据项里的码块片长与 F 项数顺序累加出每片码块与 F 列表的首地址，随机读时直接给首地址。环形回绕只在核内、由 CCU 做：地址 = 基址 + (数据块内偏移 mod $L$)，$L$ 是数据块所在环的长度（字节）；MAE 搬运的数据不按环形使用。
- **CCU-S-19** 内容已并入 **CCU-S-10**（合并重复条目，来源列在该条）。
- **CCU-S-20** **S 类读的排拍**（来自 L1_SRAM 源 §1.4、§5.2；VNU_INTEGRATION 源 §4.4、VNU_EPI 源 §3.3；V18-L1-31、V18-TP-83 (4) / TP-84 (1)、V18-EPI-05）：S 类读口一拍可接收 2 个地址，可以是同一个堆里的两个数据（架构篇 §3.4 CONC-6）；**同拍需要的多于 2 路时由 CCU 错开**。尺度与 bias 何时到达、由谁保持不作需求（归各使用者的设计者）。
